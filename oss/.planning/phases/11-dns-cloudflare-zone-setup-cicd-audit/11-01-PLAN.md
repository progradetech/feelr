<task type="checkpoint:human-action" gate="blocking">
  <name>Task 1: Add feelr.dev zone to Cloudflare and update Namecheap nameservers</name>
  <action>
    The developer must perform the following steps in browser UIs. Claude cannot automate Cloudflare dashboard or Namecheap domain panel actions.

    **Step 1: Record existing DNS (before any changes)**
    - Log into Namecheap > Domain List > feelr.dev > Advanced DNS
    - Screenshot or note ALL existing DNS records (A, CNAME, MX, TXT, etc.)
    - This is the safety net -- these records must be recreated in Cloudflare

    **Step 2: Add zone to Cloudflare**
    - Log into Cloudflare Dashboard (dash.cloudflare.com)
    - Click "Add a site" > Enter `feelr.dev`
    - Select the Free plan
    - Cloudflare will auto-scan existing DNS records -- review them carefully
    - Add any records from Step 1 that Cloudflare's scan missed
    - Do NOT add placeholder records for api/app subdomains yet (those come in Phases 12/14)
    - Note the two assigned Cloudflare nameservers (e.g., `ada.ns.cloudflare.com`, `ben.ns.cloudflare.com`)

    **Step 3: Disable DNSSEC at Namecheap (if enabled)**
    - In Namecheap > Domain List > feelr.dev > Advanced DNS
    - Check if DNSSEC is enabled (toggle at bottom of page)
    - If enabled: disable it and wait 1-2 hours before proceeding to Step 4
    - If not enabled: proceed immediately

    **Step 4: Update Namecheap nameservers**
    - In Namecheap > Domain List > feelr.dev > Domain (main settings tab)
    - Under Nameservers, select "Custom DNS"
    - Enter the two Cloudflare nameservers EXACTLY as shown (copy-paste, do not type manually)
    - Save changes

    **Step 5: Trigger Cloudflare check**
    - Return to Cloudflare dashboard > feelr.dev zone
    - Click "Check nameservers" (or "Done, check nameservers")
    - Zone status will show "Pending" until propagation completes
    - Cloudflare sends an email when zone becomes Active

    **Step 6: Verify SSL settings**
    - Once zone is Active, go to SSL/TLS in Cloudflare dashboard
    - Ensure mode is set to "Full" (not "Off" or "Flexible")
    - This ensures .dev HSTS requirements are met
  </action>
  <resume-signal>Type "zone active" once Cloudflare shows the feelr.dev zone as Active (you'll get an email). If the zone is still Pending after 24 hours, describe the issue. DNS propagation typically takes 15 minutes to 24 hours.</resume-signal>
</task>

<task type="auto">
  <name>Task 2: Verify DNS propagation and zone health</name>
  <files></files>
  <action>
    After the developer confirms zone is active, run DNS verification commands to confirm propagation:

    1. Check nameservers via Cloudflare DNS (bypass cache):
       `dig feelr.dev NS @1.1.1.1`
       Expected: ANSWER section shows two `*.ns.cloudflare.com` nameservers

    2. Check nameservers via Google DNS:
       `dig feelr.dev NS @8.8.8.8`
       Expected: Same Cloudflare nameservers

    3. Check DNSSEC is not causing issues:
       `dig +dnssec feelr.dev`
       Expected: No SERVFAIL, no AD flag (DNSSEC should be disabled at this point)

    4. Verify the zone is resolving (no NXDOMAIN):
       `dig feelr.dev SOA @1.1.1.1`
       Expected: SOA record from Cloudflare

    Report results to the developer. If any checks fail, diagnose the issue (common causes: nameserver typo, DNSSEC still active, propagation incomplete).
  </action>
  <verify>
    `dig feelr.dev NS @1.1.1.1` returns Cloudflare nameservers in ANSWER section.
    `dig feelr.dev NS @8.8.8.8` returns same Cloudflare nameservers.
  </verify>
  <done>Both Cloudflare and Google DNS resolvers return Cloudflare nameservers for feelr.dev. Zone is confirmed Active.</done>
</task>
