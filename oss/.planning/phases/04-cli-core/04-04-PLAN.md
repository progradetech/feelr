**cli/cmd/tools.go:**

Create the `tools` subcommand:
```
Use:   "tools [connector[.action]]"
Short: "Discover connectors and actions"
Long:  "Progressive discovery of available connectors and actions.\n\n  feelr tools                    List all connectors\n  feelr tools github             List actions for a connector\n  feelr tools github.issues.list Show parameter schema for an action"
Args:  cobra.MaximumNArgs(1)
```

Add a local `--schema` flag (bool, default false) for JSON Schema output on action detail.

**RunE implementation -- three levels based on args:**

**Level 0: No args (`feelr tools`)**
- Call `client.GetTools("")` -> GET /v1/tools
- Format the connector list. For default/table format, show a human-readable list:
  ```
  CONNECTOR    VERSION   ACTIONS   AUTH
  github       0.1.0     10        bearer_token
  ```
- For JSON format, output the data field directly
- For minimal format: one connector per line, pipe-delimited: `github|0.1.0|10|bearer_token`

**Level 1: Connector arg (`feelr tools github`)**
- Parse arg: if no dot, it's a connector name
- Call `client.GetTools("/github")` -> GET /v1/tools/github
- Format the action list. For default/table format:
  ```
  github - GitHub

  ACTIONS:
    issues.list      Lists issues for a repository (excludes pull requests)    list
    issues.create    Creates a new issue in a repository                       single
    ...
  ```
- For JSON/minimal: formatted list of actions

**Level 2: Connector.action arg (`feelr tools github.issues.list`)**
- Parse arg: split on first dot to get connector and action (be careful -- action names contain dots like "issues.list", so split connector as everything before first dot, action as everything after)
- Actually, re-examine: connector names are single words ("github"), action names use dots ("issues.list"). So split on first dot: connector = "github", remainder = "issues.list"
- Call `client.GetTools("/github/issues.list")` -> GET /v1/tools/github/issues.list
  - NOTE: The gateway route is /:connector/:action where action can contain dots. But the tools route is /v1/tools/:connector/:action. Since the action name "issues.list" contains a dot, we need to handle this. The gateway tools route expects the action name as the second path segment. So URL is /v1/tools/github/issues.list (Hono matches "issues.list" as the :action param).

- If `--schema` flag is set: output raw JSON data (the action schema as JSON)
- If not `--schema`: human-readable help-style output:
  ```
  github.issues.list - Lists issues for a repository (excludes pull requests)

  PARAMETERS:
    repo       string  (required)  Repository in "owner/repo" format
    state      string  (optional)  Filter by state: open, closed, or all [default: open]
    labels     string  (optional)  Comma-separated label names to filter by
    sort       string  (optional)  Sort by: created, updated, or comments [default: created]
    per_page   number  (optional)  Results per page (max 100) [default: 30]

  Returns: list
  ```
- For table/minimal formats: appropriate tabular/compact output

**Argument parsing helper:**
Create a `parseToolsArg(arg string) (connector, action string)` function:
- If arg contains a dot: connector = substring before first dot, action = substring after first dot
- If no dot: connector = arg, action = ""

**Register with root:** Add `toolsCmd` to root in init() in root.go.

**Error handling:**
- Gateway 404 (connector or action not found) -> CLIError exit code 3
- Auth errors -> CLIError exit code 2
