**cli/cmd/run.go:**

Create the `run` subcommand:
```
Use:   "run <connector> <action> [key=value...]"
Short: "Execute a connector action"
Long:  "Execute a connector action via the Feelr gateway.\n\nParameters are passed as key=value pairs after the action name.\nSystem flags (--format, --verbose, --dry-run, --cursor) are separate from action params."
Args:  cobra.MinimumNArgs(2)
```

Add a `--cursor` flag (string, local to run command) for pagination.

**RunE implementation:**

1. Extract connector (args[0]) and action (args[1])
2. Parse key=value params from args[2:]:
   - For each arg, use `strings.Cut(arg, "=")` to split on first `=`
   - If no `=` found, return CLIError with exit code 4 and message: `invalid parameter "{arg}": expected key=value format (example: repo=owner/repo)`
   - Store in `map[string]string`
3. Load config: `config.Load(profileFlag)` -- get gateway URL and API key
   - If API key is empty, return CLIError with exit code 2 and message directing user to run `feelr init` or set FEELR_API_KEY
4. Create gateway client: `client.NewGatewayClient(gatewayURL, apiKey)`
   - If `--gateway` flag is set, override config gateway URL
5. Handle `--dry-run`:
   - Build the request via `client.BuildRequest("POST", "/v1/{connector}/{action}", body)`
   - Use `httputil.DumpRequestOut(req, true)` to dump the full request
   - Print dump to stderr (data stream is stdout, debug info is stderr)
   - Return nil (exit 0)
6. Read the `--cursor` flag value. Pass it directly as the `cursor` parameter to `client.Run()`. The client.Run signature is `Run(connector, action string, params map[string]string, cursor string)` -- cursor is handled as a URL query parameter by the client (appended as `?cursor=X`), NOT mixed into the params body. Pass empty string `""` when no cursor is specified.
7. Create formatter: `output.NewFormatter(formatFlag, verboseFlag, colorFlag, os.Stdout, os.Stderr)`
8. Call `formatter.FormatData(response.Data, response.Meta)` for successful responses
9. On error from client: `formatter.FormatError(err)`, then return the error (for exit code)

**Error to exit code mapping (in client or run command):**
- Gateway error with hint="auth" -> CLIError exit code 2
- Gateway error with code containing "NOT_FOUND" -> CLIError exit code 3
- Other gateway errors -> CLIError exit code 1
- Network/timeout errors -> CLIError exit code 1
- Parameter validation errors -> CLIError exit code 4

**In root.go:**
- Add `runCmd` to root command in init(): `rootCmd.AddCommand(runCmd)`
- Wire up a PersistentPreRunE on rootCmd that reads global flag values and stores them in package-level vars (or a shared context struct) so subcommands can access them. Alternatively, read flags directly in each command's RunE via `cmd.Flags().GetString("format")` etc.

**Important implementation notes:**
- Use `fmt.Fprintln(os.Stderr, ...)` for ALL error/debug output (per stream separation decision)
- Use the formatter for ALL data output to stdout
- Do NOT call os.Exit() inside RunE -- return errors, let main.go handle exit codes
- Full connector names only, no alias resolution (per user decision)
