<task type="auto">
  <name>Task 1: Create /status route with shallow and deep health checks</name>
  <files>
    apps/gateway/src/routes/status.ts
  </files>
  <action>
    Create `apps/gateway/src/routes/status.ts` as a new Hono route module.

    **Route: GET /status**
    - Authenticated via `apiKeyMiddleware` (locked decision: rate limit info is per-token context)
    - No query params needed for shallow check
    - `?deep=true` triggers deep check

    **Implementation:**

    1. Create a new OpenAPIHono instance with AppEnv type (same pattern as other route files).

    2. Apply `apiKeyMiddleware` to the route.

    3. Handler logic:
       a. Start with gateway health: `{ status: 'healthy', version: '1.0.0' }`
       b. Get list of connectors with stored credentials via `listCredentials(c.env.AUTH_KV)`
       c. For each connector that has credentials (in Phase 3, only "github"):
          - Retrieve the decrypted credential via `getCredential(connectorName, c.env.AUTH_KV, c.env.ENCRYPTION_KEY)`
          - If credential exists and connector is "github":
            - **Shallow check (default):** Call `https://api.github.com/rate_limit` with the PAT in Authorization header, User-Agent, Accept, and X-GitHub-Api-Version headers. This endpoint is free (doesn't count against quota). Extract rate limit info from the response body: `resources.core.remaining`, `.limit`, `.used`, `.reset`.
            - **Deep check (?deep=true):** Also call `https://api.github.com/user` to verify PAT validity. Extract `login` from response.
          - Determine connector status:
            - `healthy`: rate_limit call succeeded
            - `degraded`: rate_limit remaining is 0 (quota exhausted)
            - `unhealthy`: rate_limit call failed (network error, bad PAT)
            - If deep check and /user fails: `unhealthy` (PAT invalid/expired)

    4. Response shape (wrapped in standard envelope via `wrapResponse`):
       ```typescript
       {
         ok: true,
         data: {
           gateway: { status: 'healthy', version: '1.0.0' },
           connectors: {
             github: {
               status: 'healthy' | 'degraded' | 'unhealthy',
               rate_limit: {
                 remaining: 4999,
                 limit: 5000,
                 used: 1,
                 resets_at: '2026-02-06T12:00:00Z'  // ISO 8601 from epoch
               },
               // Only if ?deep=true and successful:
               authenticated_as: 'octocat'
             }
           }
         },
         meta: { request_id, connector: 'gateway', action: 'status', duration_ms }
       }
       ```

    5. Error handling:
       - Wrap each connector health check in try/catch -- a failed check should report `unhealthy` for that connector, not crash the entire status response
       - If no credentials are stored for any connector, return an empty `connectors` object (not an error)
       - The overall response is always `ok: true` even if a connector is unhealthy -- the gateway itself is healthy, individual connectors may not be

    6. GitHub API calls in the status endpoint should use raw `fetch` (not `githubFetch` from the connector package) since this is a gateway-level route, not a connector action. Include the required headers:
       - `Authorization: Bearer ${credential.accessToken}`
       - `Accept: application/vnd.github+json`
       - `X-GitHub-Api-Version: 2022-11-28`
       - `User-Agent: Feelr/1.0`

    7. Convert the `reset` epoch timestamp to ISO 8601: `new Date(reset * 1000).toISOString()` and store as `resets_at` in the response.

    Export as `statusRoutes`.
  </action>
