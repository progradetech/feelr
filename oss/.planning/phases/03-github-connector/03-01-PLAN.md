  <action>
    **githubFetch helper (`connectors/github/src/github-fetch.ts`):**

    Create the shared GitHub API fetch helper with these responsibilities:

    1. **Interface definitions:**
       - `GitHubFetchOptions`: `{ path, method?, body?, params?, credential, fetch }`
       - `GitHubRateLimit`: `{ remaining, limit, used, reset }` (reset is epoch seconds)
       - `GitHubPagination`: `{ nextPage?, hasMore }`
       - `GitHubFetchResult<T>`: `{ data: T, rateLimit, pagination }`

    2. **`githubFetch<T>` function:**
       - Base URL: `https://api.github.com`
       - Required headers on EVERY request:
         - `Authorization: Bearer ${credential}`
         - `Accept: application/vnd.github+json`
         - `X-GitHub-Api-Version: 2022-11-28`
         - `User-Agent: Feelr/1.0`
       - Add `Content-Type: application/json` for requests with body
       - Build URL with query params (skip undefined/empty values)
       - Extract `x-ratelimit-*` headers into GitHubRateLimit object
       - Parse Link header for pagination via `parseLinkHeader`
       - On non-OK response, call `mapGitHubError` (throws, never returns)
       - On 204 (No Content -- merge response), return empty object as data
       - Parse JSON response and return `GitHubFetchResult<T>`

    3. **`parseLinkHeader` function (not exported):**
       - Input: `string | null` (the Link header value)
       - Split on `, ` to get individual links
       - Find the link with `rel="next"`
       - Extract page number from the URL's `page` query param
       - Return `{ hasMore: true, nextPage: N }` if found, `{ hasMore: false }` otherwise

    4. **`mapGitHubError` function (not exported):**
       - Import `FeelrError` from `@feelr/connector-sdk`
       - Parse response body as JSON (try/catch for non-JSON errors)
       - Map HTTP status codes to FeelrError:
         - **401**: `AUTH_INVALID` / hint: auth / status: 401 / detail: GitHub's message
         - **403 + rate limit**: Check `rateLimit.remaining === 0` OR message includes "rate limit" or "abuse detection" -> `RATE_LIMITED` / hint: retry / status: 429 / detail: reset time + limits
         - **403 (other)**: `FORBIDDEN` / hint: auth / status: 403 / detail: message + "PAT may lack required scope"
         - **404**: `NOT_FOUND` / hint: abort / status: 404 / detail: message + disambiguation note about GitHub 404 ambiguity
         - **422**: `VALIDATION_ERROR` / hint: abort / status: 400 / detail: **FORWARD GitHub's `errors` array as JSON string** (locked decision: agents need field-level validation errors)
         - **429**: `RATE_LIMITED` / hint: retry / status: 429 / detail: Retry-After header value or reset time
         - **500+**: `UPSTREAM_ERROR` / hint: retry / status: 502 / detail: message

    Export only `githubFetch` and the type interfaces (`GitHubFetchOptions`, `GitHubRateLimit`, `GitHubPagination`, `GitHubFetchResult`).

    **Flatten functions (`connectors/github/src/flatten.ts`):**

    Create per-resource flattening functions. Each takes a `Record<string, unknown>` (raw GitHub JSON) and returns a flat `Record<string, unknown>`.

    1. **`flattenIssue`** (13 fields):
       `id`, `number`, `state`, `state_reason` (nullable), `title`, `body` (default ''), `user_login` (from `user.login`, nullable), `assignee_login` (from `assignee.login`, nullable), `labels` (array of label name strings from `labels[].name`), `comments`, `created_at`, `updated_at`, `closed_at` (nullable)

    2. **`flattenPullRequest`** (15 fields):
       `id`, `number`, `state`, `title`, `body` (default ''), `user_login` (from `user.login`, nullable), `head_ref` (from `head.ref`), `head_sha` (from `head.sha`), `base_ref` (from `base.ref`), `merged` (boolean), `mergeable` (nullable), `labels` (array of name strings), `created_at`, `updated_at`, `merged_at` (nullable)

    3. **`flattenRepository`** (12 fields):
       `id`, `name`, `full_name`, `private`, `description` (nullable), `language` (nullable), `default_branch`, `stargazers_count`, `forks_count`, `open_issues_count`, `created_at`, `updated_at`

    Use safe access patterns: `(raw.user as any)?.login ?? null` for nested objects. All date fields are ISO 8601 (pass through GitHub's native format, no conversion needed -- per research recommendation).

    Export all three functions.
  </action>
