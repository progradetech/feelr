  <name>Task 1: Define runtime abstraction interfaces</name>
  <files>apps/gateway/src/runtime/interfaces.ts</files>
  <action>
Create `apps/gateway/src/runtime/interfaces.ts` with TypeScript interfaces that abstract the 4 Cloudflare binding types used by the gateway:

1. **KeyValueStore** -- replaces `KVNamespace`. Methods (all async):
   - `get(key: string): Promise<string | null>`
   - `get<T>(key: string, type: 'json'): Promise<T | null>` (overload)
   - `put(key: string, value: string): Promise<void>`
   - `delete(key: string): Promise<void>`
   - `list(options?: { prefix?: string }): Promise<{ keys: Array<{ name: string }> }>`

   These are the exact KVNamespace methods the gateway uses (verified from api-key.ts, credentials.ts, keys.ts, internal.ts). Do NOT include methods the gateway doesn't use (getWithMetadata, etc.).

2. **UsageDatabase** -- replaces `D1Database`. Only method used:
   - `prepare(sql: string): PreparedStatement`

   **PreparedStatement** interface:
   - `bind(...values: unknown[]): BoundStatement`
   - `all<T>(): Promise<{ results: T[] }>`
   - `first<T>(): Promise<T | null>`
   - `run(): Promise<{ meta: { changes?: number } }>`

   **BoundStatement** interface (extends PreparedStatement semantics):
   - `all<T>(): Promise<{ results: T[] }>`
   - `first<T>(): Promise<T | null>`
   - `run(): Promise<{ meta: { changes?: number } }>`

   Match the D1 API shape exactly as used in usage-recorder.ts, internal.ts, and scheduled.ts.

3. **RateLimiter** -- replaces `RateLimitBinding`:
   - `limit(options: { key: string }): Promise<{ success: boolean }>`

4. **TokenCoordinatorClient** -- replaces `DurableObjectNamespace` access pattern. This abstracts the "get DO stub and call RPC" pattern:
   - `getStub(): TokenCoordinatorStub`

   **TokenCoordinatorStub** interface:
   - `storeCredential(connector: string, accessToken: string, refreshToken: string, expiresAt: number): Promise<void>`
   - `removeCredential(connector: string): Promise<void>`
   - `listCredentials(): Promise<Array<{ connector: string; status: string; expiresAt: number }>>`

   These match the RPC methods used in admin.ts and credentials.ts.

5. **FeelrConfig** -- runtime config type:
   - `runtime: 'cloud' | 'self-hosted'`
   - `billing: { enabled: boolean }`
   - `encryption: { enabled: boolean }`

Export all interfaces. No implementation, just types.

  <action>
Create 4 Cloudflare adapter classes that wrap the real Cloudflare bindings behind the abstract interfaces. These are THIN wrappers -- they delegate directly to the underlying binding.

1. **CloudflareKvAdapter** (`cloudflare/kv-adapter.ts`):
   - Constructor takes `KVNamespace`
   - Implements `KeyValueStore` by delegating every method to the KVNamespace
   - `get(key, type?)` delegates to `this.kv.get(key, type)`
   - `put/delete/list` delegate directly

2. **CloudflareDbAdapter** (`cloudflare/db-adapter.ts`):
   - Constructor takes `D1Database`
   - Implements `UsageDatabase` by returning wrapped prepared statements
   - `prepare(sql)` returns a `CloudflarePreparedStatement` wrapper
   - `CloudflarePreparedStatement` wraps `D1PreparedStatement`, delegates `bind/all/first/run`
   - `CloudflareBoundStatement` wraps bound result, delegates `all/first/run`

3. **CloudflareRateLimiterAdapter** (`cloudflare/rate-limiter-adapter.ts`):
   - Constructor takes the existing `RateLimitBinding` (from lib/types.ts)
   - Implements `RateLimiter` by delegating `limit()` directly

4. **CloudflareTokenCoordinatorAdapter** (`cloudflare/token-coordinator-adapter.ts`):
   - Constructor takes `DurableObjectNamespace`
   - Implements `TokenCoordinatorClient`
   - `getStub()` returns `this.ns.idFromName('default')` -> `this.ns.get(id)` cast to `TokenCoordinatorStub`
   - The real DO already implements the RPC methods, so the cast is type-safe

Import types from `../interfaces.ts`. Import Cloudflare types from `@cloudflare/workers-types` or use the global types available in the project. Use the existing `RateLimitBinding` interface from `../../lib/types.ts` for the rate limiter.

Each adapter class should be minimal -- no logic beyond delegation.
