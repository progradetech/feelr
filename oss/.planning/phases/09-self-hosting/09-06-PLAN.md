Create a multi-stage Dockerfile that builds the self-hosted Feelr image.

**Stage 1: builder** -- Build gateway bundle and dashboard static export
```dockerfile
FROM node:22-alpine AS builder

# Install pnpm
RUN corepack enable && corepack prepare pnpm@latest --activate

WORKDIR /build

# Copy monorepo package files for dependency installation
COPY package.json pnpm-lock.yaml pnpm-workspace.yaml turbo.json ./
COPY apps/gateway/package.json apps/gateway/
COPY apps/dashboard/package.json apps/dashboard/
COPY packages/connector-sdk/package.json packages/connector-sdk/
COPY packages/tsconfig/package.json packages/tsconfig/
COPY connectors/github/package.json connectors/github/
COPY connectors/slack/package.json connectors/slack/
COPY connectors/stripe/package.json connectors/stripe/
COPY connectors/discord/package.json connectors/discord/

# Install dependencies
RUN pnpm install --frozen-lockfile

# Copy full source
COPY . .

# Build dashboard static export
RUN cd apps/dashboard && npx next build

# Bundle gateway for self-hosted mode
# Use esbuild to bundle self-hosted-entry.ts into a single JS file
RUN cd apps/gateway && npx esbuild src/self-hosted-entry.ts \
    --bundle \
    --outfile=dist/self-hosted-entry.js \
    --format=esm \
    --platform=neutral \
    --target=esnext \
    --external:cloudflare:workers \
    --minify
```

**Stage 2: runtime** -- Minimal image with workerd + s6-overlay
```dockerfile
FROM debian:bookworm-slim AS runtime

# Install s6-overlay
ARG S6_OVERLAY_VERSION=3.2.0.2
ADD https://github.com/just-containers/s6-overlay/releases/download/v${S6_OVERLAY_VERSION}/s6-overlay-noarch.tar.xz /tmp
ADD https://github.com/just-containers/s6-overlay/releases/download/v${S6_OVERLAY_VERSION}/s6-overlay-x86_64.tar.xz /tmp
RUN tar -C / -Jxpf /tmp/s6-overlay-noarch.tar.xz && \
    tar -C / -Jxpf /tmp/s6-overlay-x86_64.tar.xz && \
    rm /tmp/s6-overlay-*.tar.xz

# Install workerd
# Use the official Cloudflare workerd binary
RUN apt-get update && \
    apt-get install -y --no-install-recommends ca-certificates wget && \
    wget -qO /usr/local/bin/workerd "https://github.com/cloudflare/workerd/releases/download/v1.20250205.0/workerd-linux-64" && \
    chmod +x /usr/local/bin/workerd && \
    apt-get purge -y wget && \
    apt-get autoremove -y && \
    rm -rf /var/lib/apt/lists/*

# Create data directory
RUN mkdir -p /data/feelr/do /app/dashboard-static /etc/feelr

# Copy built artifacts
COPY --from=builder /build/apps/gateway/dist/self-hosted-entry.js /app/gateway/dist/
COPY --from=builder /build/apps/dashboard/out/ /app/dashboard-static/

# Copy workerd config
COPY config.capnp /etc/feelr/config.capnp

# Copy s6 service definitions
COPY s6/ /etc/s6-overlay/

# Copy config templates (for init script usage)
COPY feelr.yaml.template /etc/feelr/feelr.yaml.template
COPY env.template /etc/feelr/env.template

# Health check
HEALTHCHECK --interval=30s --timeout=5s --retries=3 \
    CMD wget -q --spider http://localhost:8080/health || exit 1

# Expose port
EXPOSE 8080

# Data volume
VOLUME /data/feelr

# s6-overlay entrypoint
ENTRYPOINT ["/init"]
```

Key decisions:
- debian:bookworm-slim (not alpine) because workerd may need glibc
- s6-overlay v3 for PID 1 management, process supervision, graceful shutdown
- workerd binary installed directly from GitHub releases
- esbuild bundles the self-hosted entry point into a single JS file (resolves all monorepo imports)
- `--external:cloudflare:workers` ensures the cloudflare:workers import is left as-is (workerd provides it at runtime)
- Dashboard static export copied directly (no Node.js server needed -- workerd disk service serves it)

Note: The workerd download URL and version may need adjustment. Use a stable release tag. If the direct binary download doesn't work, an alternative is to use the `ghcr.io/cloudflare/workerd` image as a base or install via npm.

**docker-compose.yml** -- Main compose file per user decision:
```yaml
services:
  feelr:
    build: .
    ports:
      - "${FEELR_PORT:-8080}:8080"
    volumes:
      - feelr-data:/data/feelr
      - ./feelr.yaml:/etc/feelr/feelr.yaml:ro
    env_file:
      - .env
    healthcheck:
      test: ["CMD", "wget", "-q", "--spider", "http://localhost:8080/health"]
      interval: 30s
      timeout: 5s
      retries: 3
    restart: unless-stopped

  caddy:
    image: caddy:2-alpine
    profiles: ["tls"]
    ports:
      - "443:443"
      - "80:80"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy-data:/data
      - caddy-config:/config
    depends_on:
      feelr:
        condition: service_healthy
    restart: unless-stopped

volumes:
  feelr-data:
  caddy-data:
  caddy-config:
```

Per user decision: Caddy is profile-based (`profiles: ["tls"]`), so it only starts with `docker compose --profile tls up`. HTTP-only by default.

**Caddyfile** -- Template for TLS reverse proxy:
```
{$FEELR_DOMAIN:localhost} {
    reverse_proxy feelr:8080
}
```

Simple Caddy config. `$FEELR_DOMAIN` env var sets the domain for Let's Encrypt. Defaults to localhost for local dev.

**s6 service definitions:**

`s6/workerd/run` (type: longrun):
```bash
#!/command/with-contenv sh
# Start workerd with the Feelr gateway configuration
exec workerd serve /etc/feelr/config.capnp 2>&1
```

`s6/workerd/finish` (handle crashes):
```bash
#!/command/with-contenv sh
# If workerd exits unexpectedly, log and let s6 handle restart
echo "workerd exited with code $1, signal $2"
```

Note: s6-overlay v3 uses `/etc/s6-overlay/s6-rc.d/` for service definitions. The correct structure is:

```
s6/s6-rc.d/workerd/
  type     (contains: longrun)
  run      (the start script)
  finish   (optional exit handler)
s6/s6-rc.d/user/
  contents.d/
    workerd  (empty file, marks workerd as a user service)
```

Create the proper s6-overlay v3 directory structure:
- `s6/s6-rc.d/workerd/type` containing `longrun`
- `s6/s6-rc.d/workerd/run` containing the start script
- `s6/s6-rc.d/workerd/finish` containing the finish script
- `s6/s6-rc.d/user/contents.d/workerd` (empty file)

`s6/cont-init.d/01-migrate.sh` (runs once at container startup):
```bash
#!/command/with-contenv sh
# Startup initialization: create data directories and set permissions

# Ensure data directories exist
mkdir -p /data/feelr/do

# Check auto-migrate flag
if [ "${FEELR_AUTO_MIGRATE}" = "false" ]; then
    echo "Auto-migration disabled (FEELR_AUTO_MIGRATE=false)"
    exit 0
fi

echo "Feelr: startup initialization complete"
# Note: SQLite schema creation happens inside workerd DOs via blockConcurrencyWhile.
# No external migration needed -- DOs auto-create their tables on first use.
```

This startup script is lightweight because the real migration happens inside the DOs (blockConcurrencyWhile in constructors). The script just ensures directories exist and logs status.

Make all scripts executable: the Dockerfile should include `RUN chmod +x /etc/s6-overlay/s6-rc.d/workerd/run /etc/s6-overlay/s6-rc.d/workerd/finish /etc/s6-overlay/cont-init.d/01-migrate.sh` or set permissions in the COPY step.

Also add to the Dockerfile `COPY` step: ensure the s6 directory structure is correct. The `COPY s6/ /etc/s6-overlay/` line copies our s6 directory directly into the overlay's config directory.
