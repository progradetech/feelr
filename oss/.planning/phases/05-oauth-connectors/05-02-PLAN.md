Create @feelr/connector-stripe following GitHub connector pattern:

1. **package.json**: Name "@feelr/connector-stripe". Same structure as GitHub connector package.

2. **tsconfig.json**: Same as GitHub's.

3. **stripe-fetch.ts**: CRITICAL -- Stripe uses form-encoded bodies, NOT JSON.
   - Base URL: `https://api.stripe.com/v1`
   - Auth header: `Authorization: Bearer <credential>` (sk_live_* or sk_test_* key)
   - User-Agent: `Feelr/1.0`
   - For GET requests: params as URL query parameters
   - For POST requests: Content-Type `application/x-www-form-urlencoded`, body encoded via `new URLSearchParams()`. Filter out undefined values before encoding. Convert all values to strings.
   - Standard HTTP error status codes (unlike Slack)
   - Error mapping:
     - 401 -> AUTH_INVALID (hint: auth)
     - 402 -> UPSTREAM_ERROR (hint: abort, detail: "Payment required")
     - 404 -> NOT_FOUND (hint: abort)
     - 429 -> RATE_LIMITED (hint: retry). Note: Stripe uses `Stripe-Rate-Limited-Reason` header (no standard Retry-After), include the reason in detail.
     - 400 -> VALIDATION_ERROR (hint: abort, include Stripe's error.message)
     - 5xx -> UPSTREAM_ERROR (hint: retry)
   - Stripe list endpoints return `{ data: T[], has_more: boolean, url: string }` -- extract pagination from has_more and last item's id for cursor
   - Interface: `StripeFetchOptions { path: string, method?: string, params?: Record<string, string | undefined>, body?: Record<string, string | undefined>, credential: string, fetch: typeof globalThis.fetch }`
   - Return: `StripeFetchResult<T> { data: T, raw: unknown, hasMore?: boolean, lastId?: string }`

4. **flatten.ts**: Flattening functions for Stripe resources:
   - `flattenPaymentIntent(raw)`: {id, amount, currency, status, description, customer, created, payment_method_types, latest_charge}
   - `flattenCustomer(raw)`: {id, email, name, phone, description, created, currency, default_source, balance}
   - `flattenInvoice(raw)`: {id, customer, status, total, currency, due_date, created, paid, hosted_invoice_url, number}

5. **utils.ts**: Same pattern as GitHub/Slack -- requireCredential, requireParam.

Run `pnpm install` from monorepo root after creating package.json.

Create 8 Stripe action handlers. Use entity.verb naming consistent with GitHub pattern.

**Read actions (6):**

1. **payments.list** (GET /v1/payment_intents):
   - Params: limit (optional, number, default 10, max 100), customer (optional, string -- filter by customer ID), status (optional, string -- requires_payment_method/requires_confirmation/succeeded/canceled)
   - Returns: list -- flattenPaymentIntent each item
   - Pagination: Use has_more + last item id as cursor. Pass ctx.cursor as `starting_after` param.

2. **payments.get** (GET /v1/payment_intents/:id):
   - Params: id (required, string -- payment intent ID, pi_*)
   - Returns: single -- flattenPaymentIntent

3. **customers.list** (GET /v1/customers):
   - Params: limit (optional, number, default 10, max 100), email (optional, string -- filter by email)
   - Returns: list -- flattenCustomer each item
   - Pagination: cursor via starting_after

4. **customers.get** (GET /v1/customers/:id):
   - Params: id (required, string -- customer ID, cus_*)
   - Returns: single -- flattenCustomer

5. **invoices.list** (GET /v1/invoices):
   - Params: limit (optional, number, default 10, max 100), customer (optional, string), status (optional, string -- draft/open/paid/void/uncollectible)
   - Returns: list -- flattenInvoice each item
   - Pagination: cursor via starting_after

6. **invoices.get** (GET /v1/invoices/:id):
   - Params: id (required, string -- invoice ID, in_*)
   - Returns: single -- flattenInvoice

**Write actions (2):**

7. **customers.create** (POST /v1/customers):
   - Params: email (optional, string), name (optional, string), phone (optional, string), description (optional, string)
   - Returns: single -- flattenCustomer
   - Body is form-encoded (handled by stripeFetch)

8. **invoices.create** (POST /v1/invoices):
   - Params: customer (required, string -- customer ID), description (optional, string), auto_advance (optional, boolean, default true)
   - Returns: single -- flattenInvoice
   - Body is form-encoded

For GET-with-ID actions (payments.get, customers.get, invoices.get): Build path as `/v1/<resource>/${id}` -- the id is a path segment, not a query param.
