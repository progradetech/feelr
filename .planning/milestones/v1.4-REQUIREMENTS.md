# v1.4 Open Core — Requirements

**Goal:** Restructure into open-core model — public repo for community contributions, private cloud overlay for billing/hosting

**Approach:** Fresh snapshot (no git history) for public repo. Git subtree integration for cloud repo consuming public repo. Provider registry pattern for billing boundary.

## AUDIT — Pre-Split Audit & Cleanup

| ID | Requirement | Priority | Notes |
|----|-------------|----------|-------|
| AUDIT-01 | Run full git history audit for secrets, credentials, and sensitive data | MUST | `git log --all -p -- '*.env*'` + Gitleaks scan |
| AUDIT-02 | Remove `self-host/.env` from git tracking and update `.gitignore` to `**/.env` | MUST | Currently tracked with test credentials |
| AUDIT-03 | Identify and migrate sensitive files (secrets inventory, internal planning docs) that should not be in public repo | MUST | `.planning/SECRETS-INVENTORY.md`, deployment tokens |
| AUDIT-04 | Run Gitleaks/truffleHog scan and produce clean report before any repo goes public | MUST | Zero findings required before proceeding |

## BILL — Billing Interface Extraction

| ID | Requirement | Priority | Notes |
|----|-------------|----------|-------|
| BILL-01 | Create `BillingProvider` interface with `enforceQuota()` and `recordUsage()` methods | MUST | Provider registry pattern |
| BILL-02 | Implement `NoopBillingProvider` that always allows requests (ships in public repo) | MUST | Default when no Stripe key present |
| BILL-03 | Extract current Stripe logic into `StripeBillingProvider` (moves to cloud repo) | MUST | Current `plan-enforcer.ts` and `meter.ts` logic |
| BILL-04 | Remove `stripe` npm dependency from public repo's `package.json` | MUST | Verify no type resolution breakage |
| BILL-05 | Extract dashboard billing UI components into cloud-only package | MUST | Pricing page, subscription management, usage meters |

## SPLIT — Repository Split

| ID | Requirement | Priority | Notes |
|----|-------------|----------|-------|
| SPLIT-01 | Create public `progradetech/feelr` repo with fresh snapshot (no history) | MUST | MIT license, full gateway + connectors + CLI + self-host + docs |
| SPLIT-02 | Create private `progradetech/feelr-cloud` repo | MUST | Proprietary cloud overlay |
| SPLIT-03 | Set up git subtree: `git subtree add --prefix=oss --squash` in cloud repo | MUST | Public repo embedded at `oss/` prefix |
| SPLIT-04 | Configure pnpm workspace overlay in cloud repo (`oss/*` + `cloud/*`) | MUST | Unified dependency graph |
| SPLIT-05 | Create cloud `wrangler.cloud.toml` with staging/production bindings | MUST | Separate from public dev-only wrangler.toml |
| SPLIT-06 | Create cloud `gateway-entry.ts` that imports OSS app and registers StripeBillingProvider | MUST | Cloud overlay entry point |
| SPLIT-07 | Verify independent builds: public repo builds and tests standalone, cloud repo builds with overlay | MUST | Both must pass CI independently |

## CICD — CI/CD Migration

| ID | Requirement | Priority | Notes |
|----|-------------|----------|-------|
| CICD-01 | Public repo CI: lint, typecheck, test only (no deploy secrets) | MUST | Contributors get CI feedback |
| CICD-02 | Cloud repo CI: full test + deploy workflows for gateway, dashboard, docs | MUST | Staging and production deploys |
| CICD-03 | Cross-repo dispatch: public repo merges trigger cloud repo sync via `repository_dispatch` | MUST | `peter-evans/repository-dispatch@v4` |
| CICD-04 | Automated subtree sync: cloud repo workflow runs `git subtree pull --prefix=oss --squash` | MUST | Triggered by dispatch event |
| CICD-05 | Fine-grained PAT scoped to `feelr-cloud` with `contents:write` + `metadata:read` | MUST | Stored as `CLOUD_REPO_PAT` in public repo |
| CICD-06 | Validate GoReleaser works from cloud repo (builds from `oss/cli/` path) | MUST | Release workflow unchanged conceptually |
