Create the `.github/ISSUE_TEMPLATE/` directory with four files:

**config.yml** -- Template chooser configuration:
- Set `blank_issues_enabled: false` to force structured forms
- Add a `contact_links` entry pointing to GitHub Discussions for general questions

**connector-request.yml** -- Connector request form:
- `name: "Connector Request"`, `description: "Request support for a new API service"`
- `title: "[connector]: "`, `labels: ["connector-request"]`
- Body elements:
  1. `markdown` block linking to existing connector requests to avoid duplicates
  2. `input` for API Service Name (required)
  3. `input` for API Documentation URL (required)
  4. `dropdown` for Authentication Type with options: "API Key", "OAuth 2.0", "Bearer Token", "No authentication (public API)" (required)
  5. `textarea` for Suggested Actions with placeholder showing dot-notation examples like "tasks.list", "tasks.create" (required)
  6. `textarea` for Additional Context (optional)

**bug-report.yml** -- Bug report form:
- `name: "Bug Report"`, `description: "Report a bug or unexpected behavior"`
- `title: "[bug]: "`, `labels: ["bug"]`
- Body elements:
  1. `textarea` for Describe the Bug (required)
  2. `textarea` for Steps to Reproduce (required)
  3. `textarea` for Expected Behavior (required)
  4. `dropdown` for Component with options: "Gateway (API)", "CLI", "Connector: GitHub", "Connector: Slack", "Connector: Stripe", "Connector: Discord", "Dashboard", "Docs", "Other" (required)
  5. `textarea` for Environment (Node.js version, OS, CLI version) (optional)

**feature-request.yml** -- Feature request form:
- `name: "Feature Request"`, `description: "Suggest an enhancement or new feature"`
- `title: "[feature]: "`, `labels: ["enhancement"]`
- Body elements:
  1. `textarea` for Description (required)
  2. `textarea` for Use Case / Motivation (required)
  3. `dropdown` for Component (same options as bug-report) (required)
  4. `textarea` for Alternatives Considered (optional)

Use the GitHub issue forms YAML syntax. Each element needs `type`, `id`, `attributes` (with `label`, `description`, `placeholder`), and `validations` (with `required`). The `dropdown` type uses `attributes.options` as an array of strings.

Do NOT add labels that reference nonexistent labels like "good first issue" on the connector-request template -- that will be handled in Plan 04 when issues are pre-seeded. Use only standard GitHub labels: "bug", "enhancement", and a simple "connector-request" label.

```markdown
- [ ] Bug fix
- [ ] Documentation
- [ ] Other: ___

- [ ] Only runtime dependency is `@feelr/connector-sdk`
- [ ] All actions use Web Standard APIs only (no `node:` or `@cloudflare` imports)
- [ ] Action descriptions are agent-optimized (50-100 tokens)
- [ ] Response data uses flat JSON with `snake_case` keys
- [ ] Tests exist in `src/__tests__/` and pass (`pnpm test`)

## Testing

<!-- How was this tested? Include test output if helpful. -->
```
