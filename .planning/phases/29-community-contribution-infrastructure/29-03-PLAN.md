**Sections to add/expand within the connector development guide:**

1. **Quick Start** (update existing): Replace the manual `cp -r` instructions with `pnpm create-connector <name> --auth <type>`. List the four auth types as options.

2. **Auth Types** (NEW section): Document all four authentication types with code examples:
   - `api_key`: API key sent in a header (e.g., `X-API-Key: ${ctx.credential}`). Used by Stripe-style APIs. Show example with header placement.
   - `oauth2`: OAuth 2.0 flow. The gateway handles token refresh; connector receives a valid access token via `ctx.credential`. Show example with `Authorization: Bearer ${ctx.credential}`.
   - `bearer_token`: Personal access token or long-lived token. Same usage as oauth2 in code (`Authorization: Bearer ${ctx.credential}`) but no refresh flow. Used by GitHub.
   - `none`: No authentication required (public APIs). `ctx.credential` is undefined; do not send auth headers.

3. **Action Patterns** (expand existing): Keep the LIST/GET/CREATE patterns but add:
   - Naming convention: `resource.verb` dot notation (e.g., `issues.list`, `repos.get`, `tasks.create`)
   - Parameter conventions: use `snake_case` names, mark required params correctly, provide defaults where sensible
   - Pagination: use `ctx.cursor` for cursor-based APIs, `meta.has_more` and `meta.cursor` for response pagination

4. **Response Normalization Rules** (NEW section):
   - Return flat JSON objects with `snake_case` keys
   - For `returns: 'list'`: `data` must be an array of objects
   - For `returns: 'single'`: `data` must be a single object
   - Include `meta` with pagination info for list actions
   - Include `raw` with the original upstream response for debugging (`?raw=true`)
   - Map upstream field names to `snake_case` (e.g., `createdAt` -> `created_at`)
   - Strip deeply nested objects -- flatten or omit

5. **Testing Patterns** (NEW section):
   - Creating mock `ActionContext` objects for testing
   - Using `@feelr/connector-test-utils` `validateConnector()` for SDK contract tests
   - Show example test file structure: import validateConnector + connector-specific tests
   - Running tests: `pnpm --filter @feelr/connector-<name> test`

6. **Error Handling** (NEW section):
   - Import `FeelrError` from `@feelr/connector-sdk`
   - Use appropriate error codes: `NOT_FOUND`, `UNAUTHORIZED`, `RATE_LIMITED`, `UPSTREAM_ERROR`, `VALIDATION`
   - Include hints for agent consumption: `{ retry_after: 60 }` for rate limits
   - Example: wrapping upstream 404 in `FeelrError('NOT_FOUND', 'Issue not found', { hint: { resource: 'issue', id: ctx.params.id } })`

Keep the existing sections intact (Getting Started, Project Structure, CLI Development, Commit Convention, Pull Requests, No CLA, Questions). Only expand the connector development portion.
