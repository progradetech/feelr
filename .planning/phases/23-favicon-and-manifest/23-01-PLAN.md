  <action>
    1. Install sharp and sharp-ico as root workspace dev dependencies:
       ```
       pnpm add -Dw sharp sharp-ico
       ```

    2. Add a `generate-icons` script to root `package.json`:
       ```json
       "generate-icons": "npx tsx scripts/generate-icons.ts"
       ```

    3. Create `scripts/generate-icons.ts` that:
       - Reads `assets/feelr-logomark.svg` as the source
       - Uses `sharp` to rasterize SVG to PNG at sizes: 16, 32, 180, 192, 512
       - Uses `sharp-ico` (`encode` function) to combine 16px + 32px PNGs into a multi-resolution ICO
       - Creates `public/` directories in both apps if they don't exist (dashboard uses `apps/dashboard/public/`, docs uses `apps/docs/public/`)
       - Writes output files to BOTH apps:
         - `apps/dashboard/src/app/favicon.ico` — 32+16 multi-res ICO
         - `apps/dashboard/src/app/apple-icon.png` — 180x180 PNG
         - `apps/dashboard/public/icon-192.png` — 192x192 PNG (for manifest)
         - `apps/dashboard/public/icon-512.png` — 512x512 PNG (for manifest)
         - `apps/docs/app/favicon.ico` — same ICO
         - `apps/docs/app/apple-icon.png` — same 180x180 PNG
         - `apps/docs/public/icon-192.png` — same 192x192 PNG
         - `apps/docs/public/icon-512.png` — same 512x512 PNG
       - Uses `import { resolve, dirname } from 'path'` and `import { writeFileSync, mkdirSync } from 'fs'` for file operations
       - Uses `import { fileURLToPath } from 'url'` with `const __dirname = dirname(fileURLToPath(import.meta.url))` for ESM compat
       - Logs each file written to stdout for verification

    4. Run the script: `pnpm generate-icons`
       - Verify all 8 output files exist and have non-zero sizes
       - Verify favicon.ico is under 15KB (should be ~2-5KB with only 32+16 sizes)

    Important: The `sharp-ico` package exports `encode(pngBuffers)` which takes an array of PNG Buffer objects and returns a Buffer containing the ICO. Check the actual API — it may be `import { encode } from 'sharp-ico'` or `import ico from 'sharp-ico'; ico.encode(...)`. Verify by checking node_modules/sharp-ico after install.

    Note: The docs app uses `app/` (no src/), while the dashboard uses `src/app/`. The script must handle both paths correctly.

<task type="auto">
  <name>Task 2: Create adaptive SVG favicon with dark/light mode for both apps</name>
  <files>
    apps/dashboard/src/app/icon.svg
    apps/docs/app/icon.svg
  </files>
  <action>
    Create an adaptive SVG favicon file based on `assets/feelr-logomark.svg` (viewBox 0 0 40 40) with CSS `prefers-color-scheme` media query for dark/light mode support. Place identical copies in both apps.

    The SVG favicon (`icon.svg`) should:
    1. Use the same paths and structure as `assets/feelr-logomark.svg` (antennae strokes, tip circles, connecting arc)
    2. Replace inline gradient `url(#markGradL)` / `url(#markGradR)` references with new gradient IDs `fgL` and `fgR` (shorter, avoids collision with any page-inlined SVGs — though as a favicon in a separate document this isn't strictly necessary, using shorter IDs is cleaner)
    3. Replace inline `fill="#fff"` on the inner tip circles (cx=5/cy=8 r=1.5 and cx=35/cy=8 r=1.5) with a CSS class `tip-inner`
    4. Add a `<style>` block with:
       - Default (dark theme — matches the dark dashboard): `.tip-inner { fill: #fff; }` (white dots on dark bg)
       - `@media (prefers-color-scheme: light)` override: `.tip-inner { fill: #1a1a2e; }` (dark dots on light bg)
    5. Set `width="32" height="32"` on the root `<svg>` element (appropriate for favicon rendering) but keep `viewBox="0 0 40 40"` for the coordinate system
    6. Keep all other elements identical: gradient definitions (Lobster Red #E85D3A to Purple #C4B5FD), stroke widths, stroke-linecap round, fill none on paths

    Write to:
    - `apps/dashboard/src/app/icon.svg`
    - `apps/docs/app/icon.svg`

    Both files are identical — same brand mark, same adaptive behavior.

    Note: Next.js file-based metadata convention will auto-detect `icon.svg` in the app directory and generate `<link rel="icon" href="/icon.svg" type="image/svg+xml" sizes="any" />` in the HTML head.
  </action>

    - `cat apps/dashboard/src/app/icon.svg` shows SVG with `prefers-color-scheme` media query
    - `cat apps/docs/app/icon.svg` shows identical SVG content
    - SVG contains `width="32" height="32"` and `viewBox="0 0 40 40"`
    - SVG contains `.tip-inner` class and both light/dark rules
    - `diff apps/dashboard/src/app/icon.svg apps/docs/app/icon.svg` shows no differences
  </verify>
  <done>
    Both apps have an identical adaptive SVG favicon that shows white inner dots on dark browser themes and dark inner dots on light browser themes. Next.js will auto-detect and serve it as the SVG icon.
  </done>
