**1. sync.yml** -- OSS subtree sync receiver (CICD-04):

```yaml
# Receive OSS updates from public repo via repository_dispatch (CICD-04)
# Also supports manual trigger for recovery
name: Sync OSS

on:
  repository_dispatch:
    types: [oss-sync]
  workflow_dispatch:

concurrency:
  group: oss-sync
  cancel-in-progress: false

jobs:
  sync:
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
          token: ${{ secrets.GITHUB_TOKEN }}

      - name: Configure git
        run: |
          git config user.name "github-actions[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"

      - name: Add OSS remote and pull subtree
        run: |
          git remote add oss https://github.com/progradetech/feelr.git
          git fetch oss main
          git subtree pull --prefix=oss oss main --squash \
            -m "chore: sync OSS subtree to ${{ github.event.client_payload.sha || 'manual' }}"

      - uses: pnpm/action-setup@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: "pnpm"

      - name: Install and update lockfile
        run: |
          pnpm install
          if ! git diff --quiet pnpm-lock.yaml 2>/dev/null; then
            git add pnpm-lock.yaml
            git commit --amend --no-edit
          fi

      - name: Build and test
        run: pnpm turbo run typecheck test

      - name: Push sync commit
        run: git push origin main
```

Key details for sync.yml:
- `fetch-depth: 0` is MANDATORY -- shallow clones break `git subtree pull` (can't find split point)
- `concurrency.cancel-in-progress: false` prevents race conditions from rapid merges
- `workflow_dispatch` enables manual recovery if automated sync fails
- Uses `pnpm install` (NOT `--frozen-lockfile`) because subtree pulls may change OSS dependencies, requiring lockfile regeneration
- If lockfile changes, amends the sync commit to keep history clean
- The public repo is public so `git fetch oss main` needs no token

Create `.github/workflows/release.yml` for GoReleaser CLI releases from the cloud repo (CICD-06):

```yaml
# GoReleaser CLI release from cloud repo subtree (CICD-06)
# Builds from oss/cli/ using workdir parameter
name: Release

on:
  push:
    tags:
      - "v*"

permissions:
  contents: write

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - uses: actions/setup-go@v5
        with:
          go-version-file: oss/cli/go.mod

      - uses: goreleaser/goreleaser-action@v6
        with:
          args: release --clean
          workdir: oss
        env:
          GITHUB_TOKEN: ${{ secrets.HOMEBREW_TAP_GITHUB_TOKEN }}
```

Key details for release.yml:
- `workdir: oss` sets GoReleaser's working directory to the subtree root where `.goreleaser.yaml` lives
- `.goreleaser.yaml` has `dir: cli` so GoReleaser resolves Go module at `oss/cli/`
- `go-version-file: oss/cli/go.mod` points setup-go to the correct module file
- `HOMEBREW_TAP_GITHUB_TOKEN` is needed for GoReleaser to push to the Homebrew tap repo
- `release.github.name: feelr` in `.goreleaser.yaml` publishes releases to the public repo (not the cloud repo)
