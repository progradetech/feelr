  <name>Task 1: Create fine-grained PAT and configure secrets</name>
  <action>
The user must create a fine-grained PAT and set up secrets in both repos.
  </action>
  <instructions>
**Step 1: Create fine-grained PAT**

1. Go to https://github.com/settings/tokens?type=beta
2. Click "Generate new token"
3. Name: `feelr-public-to-cloud-dispatch`
4. Expiration: 90 days (set a reminder to rotate)
5. Resource owner: `progradetech`
6. Repository access: "Only select repositories" -> select `progradetech/feelr-cloud`
7. Permissions:
   - Contents: Read and write
   - Metadata: Read-only (auto-selected)
8. Generate token, copy the value

**Step 2: Add CLOUD_REPO_PAT to public repo**

```bash
gh secret set CLOUD_REPO_PAT --repo progradetech/feelr --body "<paste-token-here>"
```

Or if you prefer not to use --body (avoids shell history):
```bash
gh secret set CLOUD_REPO_PAT --repo progradetech/feelr
# Then paste the token when prompted
```

**Step 3: Add deployment secrets to cloud repo**

These are the same secrets that were in the public repo before the split. You will need the original values from your credential store. For each secret, run:

```bash
gh secret set CLOUDFLARE_API_TOKEN --repo progradetech/feelr-cloud
gh secret set CLOUDFLARE_ACCOUNT_ID --repo progradetech/feelr-cloud
gh secret set SWA_DASHBOARD_STAGING_TOKEN --repo progradetech/feelr-cloud
gh secret set SWA_DASHBOARD_DEPLOYMENT_TOKEN --repo progradetech/feelr-cloud
gh secret set SWA_DOCS_STAGING_TOKEN --repo progradetech/feelr-cloud
gh secret set SWA_DOCS_DEPLOYMENT_TOKEN --repo progradetech/feelr-cloud
gh secret set HOMEBREW_TAP_GITHUB_TOKEN --repo progradetech/feelr-cloud
gh secret set CF_ANALYTICS_TOKEN_STAGING --repo progradetech/feelr-cloud
gh secret set CF_ANALYTICS_TOKEN_PRODUCTION --repo progradetech/feelr-cloud
```

**Step 4: Create production environment on cloud repo**

```bash
gh api --method PUT repos/progradetech/feelr-cloud/environments/production
```

**Check 4: Verify cross-repo dispatch**
Trigger a test dispatch from the public repo to verify the chain:
```bash
gh api --method POST repos/progradetech/feelr-cloud/dispatches \
  -f event_type=oss-sync \
  -f 'client_payload[sha]=test-verification' \
  -f 'client_payload[ref]=refs/heads/main'
```

Wait ~30 seconds, then check if the cloud repo's sync workflow was triggered:
```bash
gh run list --repo progradetech/feelr-cloud --workflow sync.yml --limit 1
```

If the workflow appears, the dispatch chain is functional. If it does not appear after 60 seconds, check:
- Does sync.yml exist on cloud repo main? (`gh api repos/progradetech/feelr-cloud/contents/.github/workflows/sync.yml`)
- Is the event type correct? (must be exactly `oss-sync`)

Note: The sync workflow run may fail (because it expects a real OSS commit to pull) -- that is OK for this verification. The important thing is that the workflow was triggered.

**Check 5: Verify GoReleaser snapshot build**
Clone the cloud repo and test GoReleaser:
```bash
git clone git@github.com:progradetech/feelr-cloud.git /tmp/feelr-cloud-verify
cd /tmp/feelr-cloud-verify
goreleaser build --snapshot --clean --single-target -f oss/.goreleaser.yaml
```

If `goreleaser` is not installed locally, this check can be skipped -- the release.yml workflow in the cloud repo will validate it on the first v* tag push. Instead, verify the configuration is correct:
```bash
ls /tmp/feelr-cloud-verify/oss/.goreleaser.yaml
ls /tmp/feelr-cloud-verify/oss/cli/go.mod
grep 'dir: cli' /tmp/feelr-cloud-verify/oss/.goreleaser.yaml
```

Clean up: `rm -rf /tmp/feelr-cloud-verify`

**Check 6: Verify public repo workflows are clean**
