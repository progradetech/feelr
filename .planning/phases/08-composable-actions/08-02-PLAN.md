<feature>
  <name>Template Selector Resolution Engine</name>
  <files>cli/internal/chain/selector.go, cli/internal/chain/selector_test.go</files>
  <behavior>
The selector engine resolves `${{ expression }}` templates within string values.

Resolution context has two namespaces:
- `params`: Runtime parameters (map[string]string)
- `steps`: Step outputs (map[string]interface{} keyed by step ID)

Expression types:
1. Simple field: `${{ params.repo }}` -> "owner/repo"
2. Nested field: `${{ steps.create_issue.user.login }}` -> "octocat"
3. Array index: `${{ steps.list.items[0].name }}` -> "first"
4. Null coalesce: `${{ steps.x.name ?? 'fallback' }}` -> "fallback" if nil
5. Mixed string: `Issue #${{ steps.x.number }} in ${{ params.repo }}` -> "Issue #42 in owner/repo"
6. Whole expression: `${{ steps.x.number }}` -> "42" (stringified)

Missing data behavior: returns empty string (lenient mode). No error on missing fields -- chains should work even if optional fields are absent.

Cases:
- `ResolveTemplate("${{ params.repo }}", ctx)` -> "owner/repo"
- `ResolveTemplate("${{ steps.create.number }}", ctx)` -> "42"
- `ResolveTemplate("${{ steps.create.user.login }}", ctx)` -> "octocat"
- `ResolveTemplate("${{ steps.list.data[0].title }}", ctx)` -> "First Issue"
- `ResolveTemplate("${{ steps.missing.field ?? 'default' }}", ctx)` -> "default"
- `ResolveTemplate("Issue #${{ steps.create.number }}", ctx)` -> "Issue #42"
- `ResolveTemplate("no templates here", ctx)` -> "no templates here"
- `ResolveTemplate("${{ steps.missing.field }}", ctx)` -> ""
- `ResolveTemplate("${{ params.missing }}", ctx)` -> ""
  </behavior>
  <implementation>
1. Define a `ResolveContext` struct holding params (map[string]string) and steps (map[string]interface{}).

2. Implement `ResolveTemplate(template string, ctx *ResolveContext) string`:
   - Use regex `\$\{\{\s*(.+?)\s*\}\}` to find all template expressions
   - For each match, call `resolveExpression(expr string, ctx) string`
   - Replace matches with resolved values
   - Return final string

3. Implement `resolveExpression(expr string, ctx) string`:
   - Check for null coalescing: split on ` ?? ` (with spaces)
   - Left side is the path, right side is the fallback (strip surrounding quotes)
   - Call `resolvePath(path, ctx)` -- if result is empty string and fallback exists, use fallback

4. Implement `resolvePath(path string, ctx) string`:
   - Split path on first dot to get root namespace: "params" or "steps"
   - For "params": look up remaining key in ctx.Params
   - For "steps": navigate the nested map using dot notation and bracket notation
   - Navigate using a generic `walkPath(data interface{}, segments []string) interface{}` helper
   - Handle `[N]` array index access in path segments
   - Convert final value to string via fmt.Sprintf("%v", val)

5. Implement path segment parser that splits "steps.create.data[0].title" into ["steps", "create", "data", "[0]", "title"] handling bracket notation correctly.

Do NOT use expr-lang/expr here -- that library is for condition evaluation (Plan 03). This is pure Go string interpolation with path navigation.
  </implementation>
</feature>
