<task type="auto">
  <name>Task 1: Create dispatch workflow in OSS subtree and push to public repo</name>
  <files>oss/.github/workflows/sync.yml</files>
  <action>
Create `oss/.github/workflows/sync.yml` with the following dispatch workflow:

```yaml
name: Sync to Cloud

on:
  push:
    branches: [main]

jobs:
  dispatch:
    runs-on: ubuntu-latest
    steps:
      - uses: peter-evans/repository-dispatch@v4
        with:
          token: ${{ secrets.CLOUD_REPO_PAT }}
          repository: progradetech/feelr-cloud
          event-type: oss-sync
          client-payload: '{"sha": "${{ github.sha }}"}'
```

Key details:
- Triggers on push to main (catches both PR merges and direct pushes)
- Uses `peter-evans/repository-dispatch@v4` (the same action from the old workflow)
- Secret name: `CLOUD_REPO_PAT` -- a Personal Access Token with `repo` scope on the cloud repo
- Event type: `oss-sync` -- matches the cloud repo's sync.yml `repository_dispatch.types`
- Passes the commit SHA in the payload for traceability

After creating locally, commit to the cloud repo. Then push the file to the public repo using SSH git clone/push (same pattern as 30-01 since gh API may have scope issues):

```bash
# Clone public repo
git clone git@github.com:progradetech/feelr.git /tmp/feelr-public
# Copy the workflow file
cp oss/.github/workflows/sync.yml /tmp/feelr-public/.github/workflows/sync.yml
# Commit and push
cd /tmp/feelr-public
git add .github/workflows/sync.yml
git commit -m "ci: add dispatch workflow to trigger cloud repo sync on push to main"
git push origin main
```

NOTE: The public repo needs a `CLOUD_REPO_PAT` secret configured. Check if it exists; if not, this will need to be set up manually by the user.
