Create the @feelr/connector-slack package following the GitHub connector pattern exactly:

1. **package.json**: Copy structure from @feelr/connector-github. Name: "@feelr/connector-slack". Same deps (only @feelr/connector-sdk workspace:*). Same devDeps pattern.

2. **tsconfig.json**: Identical to GitHub's -- extends @feelr/tsconfig/base.json, outDir dist, include src/**/*.ts.

3. **slack-fetch.ts**: Create the shared Slack API fetch helper. CRITICAL: Slack returns HTTP 200 on errors -- the ok field in JSON body determines success/failure.
   - Base URL: `https://slack.com/api/`
   - All Slack Web API calls use POST with JSON body
   - Auth header: `Authorization: Bearer <credential>` (xoxb-* bot token)
   - Content-Type: `application/json; charset=utf-8`
   - After parsing response JSON, check `json.ok === false` to detect errors
   - Only exception: HTTP 429 is returned as actual HTTP status for rate limits
   - Error mapping function (`mapSlackError`) should map Slack error strings to FeelrError:
     - `not_authed`, `invalid_auth`, `account_inactive`, `token_revoked` -> AUTH_INVALID (401, hint: auth)
     - `token_expired` -> CREDENTIAL_EXPIRED (401, hint: auth, message includes "feelr auth slack")
     - `channel_not_found`, `user_not_found` -> NOT_FOUND (404, hint: abort)
     - `ratelimited` -> RATE_LIMITED (429, hint: retry) -- also extract Retry-After header
     - `missing_scope` -> FORBIDDEN (403, hint: auth, detail includes required scope)
     - Default -> UPSTREAM_ERROR (502, hint: abort)
   - Return type: `SlackFetchResult<T>` with `{ data: T, raw: unknown }`
   - Extract `response_metadata.next_cursor` for pagination support
   - Interface `SlackFetchOptions`: `{ method: string, params?: Record<string, unknown>, credential: string, fetch: typeof globalThis.fetch }`

4. **flatten.ts**: Create flattening functions for Slack resources:
   - `flattenChannel(raw)`: Extract {id, name, topic, purpose, num_members, is_archived, is_private, created}
   - `flattenMessage(raw)`: Extract {ts, text, user, thread_ts, reply_count, type, channel}
   - `flattenUser(raw)`: Extract {id, name, real_name, display_name, is_bot, is_admin, status_text, status_emoji}

5. **utils.ts**: Create shared utilities:
   - `requireCredential(ctx)`: Same pattern as GitHub -- throws AUTH_REQUIRED if missing, returns credential string
   - `requireParam(ctx, name)`: Extract and validate required string param, throws VALIDATION_ERROR if missing

Run `pnpm install` from monorepo root after creating package.json to link workspace dependency.

Create 6 action handlers following the GitHub issues-list.ts pattern exactly. Each action exports an ActionDefinition with name, description (50-100 tokens, 3-part: what/accepts/returns), params, returns type, and handler.

Use entity.verb naming (per research recommendation, consistent with GitHub pattern):

1. **messages.send** (Slack API: `chat.postMessage`):
   - Params: channel (required, string -- channel ID or name), text (required, string), thread_ts (optional, string -- reply to thread)
   - Returns: single -- flattened message {ts, text, channel}
   - Scope: chat:write

2. **channels.list** (Slack API: `conversations.list`):
   - Params: types (optional, default "public_channel" -- "public_channel,private_channel"), limit (optional, number, default 200, max 1000), exclude_archived (optional, boolean, default true)
   - Returns: list -- array of flattened channels
   - Pagination: Use response_metadata.next_cursor from slackFetch, pass ctx.cursor as cursor param
   - Scope: channels:read

3. **messages.search** (Slack API: `search.messages`):
   - Params: query (required, string), sort (optional, "score"/"timestamp", default "score"), count (optional, number, default 20, max 100)
   - Returns: list -- array of flattened messages (from matches.messages array)
   - Pagination: Use paging.page for cursor
   - Scope: search:read

4. **users.list** (Slack API: `users.list`):
   - Params: limit (optional, number, default 200, max 1000)
   - Returns: list -- array of flattened users
   - Pagination: cursor-based via response_metadata.next_cursor
   - Scope: users:read

5. **threads.reply** (Slack API: `chat.postMessage` with thread_ts required):
   - Params: channel (required, string), thread_ts (required, string -- parent message timestamp), text (required, string)
   - Returns: single -- flattened message
   - Scope: chat:write

6. **channels.setTopic** (Slack API: `conversations.setTopic`):
   - Params: channel (required, string -- channel ID), topic (required, string -- new topic text)
   - Returns: single -- flattened channel
   - Scope: channels:write.topic
