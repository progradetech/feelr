1. **package.json**: Name "@feelr/connector-discord". Same structure.

2. **tsconfig.json**: Same as GitHub's.

3. **discord-fetch.ts**: Discord API v10 fetch helper.
   - Base URL: `https://discord.com/api/v10`
   - Auth header: `Authorization: Bot <credential>` (NOT "Bearer" -- Discord bot tokens use "Bot" prefix)
   - Content-Type: `application/json` for POST/PUT/DELETE
   - User-Agent: `Feelr/1.0` (Discord requires User-Agent header)
   - Standard HTTP status error codes (unlike Slack)
   - Rate limit headers: `X-RateLimit-Remaining`, `X-RateLimit-Limit`, `X-RateLimit-Reset-After`
   - Extract rate limit info into a `DiscordRateLimit` type returned alongside data
   - Error mapping:
     - 401 -> AUTH_INVALID (hint: auth)
     - 403 -> FORBIDDEN (hint: auth, detail includes "bot may lack required permission")
     - 404 -> NOT_FOUND (hint: abort)
     - 429 -> RATE_LIMITED (hint: retry). Discord returns `retry_after` in JSON body AND `Retry-After` header. Include retry_after seconds in detail.
     - 400 -> VALIDATION_ERROR (hint: abort, include Discord's error message)
     - 5xx -> UPSTREAM_ERROR (hint: retry)
   - Handle 204 No Content responses (e.g., kick, ban return 204)
   - Interface: `DiscordFetchOptions { path: string, method?: string, body?: Record<string, unknown>, credential: string, fetch: typeof globalThis.fetch }`
   - Return: `DiscordFetchResult<T> { data: T, rateLimit: DiscordRateLimit, raw: unknown }`

4. **flatten.ts**: Flattening functions:
   - `flattenChannel(raw)`: {id, name, type, topic, position, nsfw, parent_id, guild_id}
   - `flattenMember(raw)`: {user_id, username, display_name, nick, roles, joined_at, is_bot}
   - `flattenRole(raw)`: {id, name, color, position, permissions, mentionable, managed}
   - `flattenMessage(raw)`: {id, content, author_id, author_username, channel_id, timestamp, type}

5. **utils.ts**: requireCredential + requireParam (same pattern).

Run `pnpm install` from monorepo root.

Create 7 Discord action handlers. All Discord endpoints require a guild_id parameter (Discord servers are called "guilds" in the API).

1. **messages.send** (POST /channels/{channel_id}/messages):
   - Params: channel_id (required, string), content (required, string)
   - Returns: single -- flattenMessage
   - Permission: Send Messages

2. **channels.list** (GET /guilds/{guild_id}/channels):
   - Params: guild_id (required, string)
   - Returns: list -- flattenChannel each item. Discord returns all channels at once (no pagination).

3. **members.list** (GET /guilds/{guild_id}/members):
   - Params: guild_id (required, string), limit (optional, number, default 100, max 1000), after (optional, string -- user ID for pagination)
   - Returns: list -- flattenMember each item
   - Pagination: If result length equals limit, set cursor to last member's user_id. Pass ctx.cursor as `after` query param.
   - Note: Requires Server Members Intent enabled in bot settings

4. **roles.list** (GET /guilds/{guild_id}/roles):
   - Params: guild_id (required, string)
   - Returns: list -- flattenRole each item. No pagination needed.

5. **roles.assign** (PUT /guilds/{guild_id}/members/{user_id}/roles/{role_id}):
   - Params: guild_id (required, string), user_id (required, string), role_id (required, string)
   - Returns: single -- { success: true, guild_id, user_id, role_id }
   - Response is 204 No Content on success -- construct return object manually
   - Permission: Manage Roles

6. **members.ban** (PUT /guilds/{guild_id}/bans/{user_id}):
   - Params: guild_id (required, string), user_id (required, string), delete_message_seconds (optional, number, default 0, max 604800 -- seconds of messages to delete)
   - Returns: single -- { success: true, guild_id, user_id }
   - Response is 204 on success
   - Permission: Ban Members

7. **members.kick** (DELETE /guilds/{guild_id}/members/{user_id}):
   - Params: guild_id (required, string), user_id (required, string)
   - Returns: single -- { success: true, guild_id, user_id }
   - Response is 204 on success
   - Permission: Kick Members
