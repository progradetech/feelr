<objective>
Integrate Stripe billing into the gateway with metered subscriptions and plan enforcement.

Purpose: Enable usage-based billing on the cloud deployment. API keys are associated with Stripe customers via `stripeCustomerId`. The billing enforcer middleware checks cached plan status from KV before dispatching requests. After successful requests, meter events are fired asynchronously via `waitUntil`. The entire billing system is gated behind `billing.enabled` from FeelrConfig -- when disabled (self-hosted default), the middleware is a zero-cost passthrough that never touches Stripe.

Output: Billing module (stripe-client, types, meter, plan-enforcer, plan-cache), updated AppEnv with STRIPE_SECRET_KEY binding, billing middleware wired into app.ts middleware chain.
</objective>

  <action>
    Create the `apps/gateway/src/billing/` directory with these modules:

    **stripe-client.ts**: Initialize Stripe SDK for Cloudflare Workers.
    - Import from `stripe/lib/stripe.js` (NOT `stripe` -- the default import pulls in Node.js modules that fail in Workers runtime).
    - Export `createStripeClient(secretKey: string)` that returns a Stripe instance with `httpClient: Stripe.createFetchHttpClient()` and pinned `apiVersion: '2025-12-18.acacia'`.
    - Export `webCrypto = Stripe.createSubtleCryptoProvider()` for future webhook signature verification.

    **types.ts**: Define billing type constants and interfaces.
    - `BillingPlan` type: `'hatchling' | 'lobster' | 'leviathan'`
    - `PLAN_LIMITS` constant mapping each plan to `{ api_calls_per_month: number, connectors: number | 'unlimited', rate_limit_rpm: number }`:
      - hatchling: 1000/month, 5 connectors, 30 RPM
      - lobster: 50000/month, unlimited, 300 RPM
      - leviathan: 500000/month, unlimited, 3000 RPM
    - `TIER_TO_PLAN` mapping: `{ free: 'hatchling', pro: 'lobster', enterprise: 'leviathan' }` to bridge between existing rate limit tiers and billing plan names.
    - `CachedPlanStatus` interface: `{ plan: BillingPlan, stripeCustomerId: string, apiCallsThisMonth: number, apiCallsLimit: number, validUntil: number }` (epoch ms TTL).

    **meter.ts**: Async Stripe meter event recording.
    - Export `recordMeterEvent(stripe: Stripe, customerId: string, value?: number)` that calls `stripe.billing.meterEvents.create({ event_name: 'feelr_api_calls', payload: { stripe_customer_id: customerId, value: String(value ?? 1) } })`.
    - Function is async, designed to be called via `waitUntil()`. Never throws -- wraps in try/catch that silently swallows errors (same pattern as usage-recorder.ts).

    **plan-cache.ts**: KV-backed plan status caching.
    - Export `getCachedPlanStatus(kv: KeyValueStore, apiKeyShort: string): Promise<CachedPlanStatus | null>` -- reads from KV at key `plan:<apiKeyShort>`, returns null if missing or expired (validUntil < Date.now()).
    - Export `setCachedPlanStatus(kv: KeyValueStore, apiKeyShort: string, status: CachedPlanStatus): Promise<void>` -- writes to KV.
    - Export `PLAN_CACHE_TTL_MS = 5 * 60 * 1000` (5 minutes).
    - Import `KeyValueStore` from `../runtime/interfaces` (NOT from Cloudflare types).

    **Update auth/types.ts**: Add optional `stripeCustomerId?: string` field to `ApiKeyRecord` interface. This links an API key to a Stripe customer for billing. Optional because self-hosted keys and free tier keys may not have Stripe associations.

    **Update package.json**: Add `"stripe": "^17.0.0"` to dependencies (latest SDK with Workers support).

    **plan-enforcer.ts**: Create the billing enforcement middleware.
    - Export `billingEnforcer` as a Hono middleware (`createMiddleware<AppEnv>`).
    - First check: `if (!c.env.FEELR_CONFIG?.billing?.enabled) return next()` -- zero-cost passthrough when billing is disabled. This MUST be the first line. When billing is disabled, the Stripe SDK should never be imported or initialized.
    - Get `apiKeyRecord` from context. If no record or no `stripeCustomerId`, treat as free tier (passthrough -- free tier has no billing enforcement beyond rate limits).
    - If `stripeCustomerId` exists: call `getCachedPlanStatus(c.env.AUTH_KV, record.shortToken)`.
    - If cache miss: For this plan, return `next()` with a warning header `X-Feelr-Billing: cache-miss` (webhook/cron will populate cache; don't block on Stripe API call in request path to avoid 100-300ms latency). In a future enhancement, a background job can populate the cache.
    - If cache hit and `apiCallsThisMonth >= apiCallsLimit`: return a 402 response with `{ ok: false, error: { code: 'PLAN_LIMIT_EXCEEDED', message: 'Monthly API call limit reached. Upgrade your plan at https://feelr.dev/pricing', hint: 'abort' }, meta: { plan: status.plan, usage: status.apiCallsThisMonth, limit: status.apiCallsLimit } }`.
    - After `await next()`: Fire meter event asynchronously via `c.executionCtx.waitUntil(...)`. Only fire if billing is enabled AND stripeCustomerId exists. Use `createStripeClient(c.env.STRIPE_SECRET_KEY)` lazily (create once per request only when needed, not at module load). Wrap in `.catch(() => {})` for best-effort (same pattern as usage-recorder).

    **Update lib/types.ts (AppEnv)**: Add to Bindings:
    - `STRIPE_SECRET_KEY?: string` -- optional Worker Secret (only present in cloud with billing enabled)

    - Import `billingEnforcer` from `./billing/plan-enforcer`.
    - Add `app.use('/v1/*', billingEnforcer)` AFTER `keyRateLimiter` and BEFORE `rateLimitHeaders` in the middleware chain. The billing check runs after rate limiting (a rate-limited request shouldn't count toward billing) but before response headers are set.
    - Update the middleware chain comment to document the new step.

    **Update wrangler.toml**: Add `STRIPE_SECRET_KEY` as a Workers Secret reference (just the name, actual value set via `wrangler secret put`). Do NOT set a default value.
