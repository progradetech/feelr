    1. Create `apps/gateway/src/billing/plan-enforcer.ts`:
       - Export `planEnforcer()` returning `MiddlewareHandler<AppEnv>`
       - First check: `if (!c.env.FEELR_CONFIG?.billing?.enabled) return next()` -- no-op for self-hosted
       - Look up customer billing from KV: key `billing:<apiKeyShort>` (JSON-parsed `CustomerBilling`)
       - If no billing record exists, treat as hatchling/free tier (default for unlinked keys)
       - Check `currentMonthUsage` against `PLAN_LIMITS[plan].api_calls_per_month`
       - If over quota: return 402 status with FeelrError code 'PLAN_QUOTA_EXCEEDED', hint 'abort', message including plan name and limit
       - If under quota: call `await next()`
       - After next(): fire meter event via waitUntil (import from meter.ts)
       - Increment cached usage count: update KV `billing:<apiKeyShort>` with currentMonthUsage+1 via waitUntil (best-effort, same pattern as usage-recorder.ts)
       - Add 'PLAN_QUOTA_EXCEEDED' to error codes. Since the gateway uses a union type ErrorCode, add it to the error codes in lib/errors.ts if needed, or use it as a string directly in the FeelrError constructor (check existing pattern).

    2. Create `apps/gateway/src/billing/meter.ts`:
       - Export `recordMeterEvent(stripe: Stripe, customerId: string, value?: number): Promise<void>`
       - Call `stripe.billing.meterEvents.create({ event_name: 'feelr_api_calls', payload: { stripe_customer_id: customerId, value: String(value ?? 1) } })`
       - Wrap in try/catch -- best-effort, never throw (same philosophy as usage-recorder.ts)
       - Export `createStripeClientFromEnv(env: AppEnv['Bindings']): Stripe | null` helper that returns null if STRIPE_SECRET_KEY is missing (safe for self-hosted)

    3. Update `apps/gateway/src/app.ts`:
       - Import `planEnforcer` from './billing/plan-enforcer'
       - Add `app.use('/v1/*', planEnforcer())` in the middleware chain AFTER keyRateLimiter and BEFORE rateLimitHeaders
       - This means the chain becomes: IP limiter -> API key auth -> key rate limiter -> plan enforcer -> rate limit headers
       - The plan enforcer runs after rate limiting so rate-limited requests (429) are not counted against the monthly quota
