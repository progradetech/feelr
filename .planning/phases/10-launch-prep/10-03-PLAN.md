<task type="auto">
  <name>Task 2: CLI update checker with daily cache</name>
  <files>
    cli/internal/update/checker.go
    cli/cmd/root.go
  </files>
  <action>
    1. Create `cli/internal/update/` directory

    2. Create `cli/internal/update/checker.go`:
       - package update
       - `CheckForUpdate(currentVersion string)` function:
         - If currentVersion is "dev", return immediately (development build)
         - Check cache file at `~/.config/feelr/update-check` (same config dir as CLI config)
         - If cache file exists and was modified within last 24 hours, read cached result
         - If cache is stale or missing:
           - Make HTTP GET to `https://api.github.com/repos/andrewprograde/feelr/releases/latest`
           - Parse response for `tag_name` field (e.g., "v1.2.3")
           - Strip "v" prefix and compare with currentVersion using simple semver comparison
           - Write result to cache file (latest version string + timestamp)
         - If newer version available, print to stderr (NOT stdout per CLI philosophy):
           `fmt.Fprintf(os.Stderr, "Update available: %s -> %s (brew upgrade feelr or visit https://github.com/andrewprograde/feelr/releases)\n", currentVersion, latest)`
         - All errors silently ignored (network errors, parse errors, file errors) -- per decision: silent check, never block CLI usage
         - Use a 5-second HTTP timeout to avoid blocking slow networks
       - `compareVersions(current, latest string) bool` helper (returns true if latest > current):
         - Split on "." and compare major, minor, patch as integers
         - Simple comparison sufficient for semver without pre-release tags

    3. Update `cli/cmd/root.go`:
       - Import update package
       - In the root command's PersistentPreRun (or PersistentPreRunE), call `go update.CheckForUpdate(version)` in a goroutine
       - The goroutine pattern means the update check happens concurrently with command execution and never delays the user
       - However, since the check writes to stderr, ensure it completes before the main command finishes by using a sync.WaitGroup or channel
       - Simpler alternative: call CheckForUpdate synchronously but early (before command execution). With the 5s timeout and cache, this adds negligible latency in the common case (cache hit = file read only).
       - Use the simpler synchronous approach: if cache is fresh (24h), it's just a file read (<1ms). Only on stale cache does it make an HTTP call (max 5s timeout).
  </action>

  </verify>
  <done>
    CLI checks for updates on every invocation with 24h cache. Cache hit is a fast file read. Cache miss makes a GitHub API call with 5s timeout. Update notification prints to stderr as a one-liner with upgrade instructions. "dev" builds skip the check entirely.
  </done>
