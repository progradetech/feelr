  <action>
    Create all documentation content pages. Read the actual connector source files (connectors/github/src/index.ts, etc.) to extract the real action names, parameters, and descriptions. Do NOT invent actions -- use the actual ConnectorDefinition.actions from each connector.

    **getting-started/page.mdx**: Quick-start guide (zero to first API call).
    - Prerequisites: Node.js, pnpm, Cloudflare account (or Docker for self-hosted)
    - Step 1: Install CLI (`brew install andrewprograde/feelr/feelr` or download from GitHub Releases)
    - Step 2: Initialize (`feelr init` -- sets gateway URL, API key)
    - Step 3: Store GitHub PAT (`feelr auth github`)
    - Step 4: Make first call (`feelr run github issues.list repo=owner/repo`)
    - Show the expected JSON response envelope: `{ ok: true, data: [...], meta: {...} }`

    **auth/setup/page.mdx**: Authentication setup.
    - How API keys work (fk_live_XXXX_YYYY format, tier system)
    - Creating keys via CLI (`feelr init`) or dashboard
    - Per-connector auth flows:
      - GitHub: PAT-based (`feelr auth github`, paste token)
      - Slack: OAuth browser flow (`feelr auth slack`, opens browser)
      - Discord: Bot token (`feelr auth discord`, paste token)
      - Stripe: API key (`feelr auth stripe`, paste sk_live_xxx)
    - Security: tokens encrypted at rest with AES-256-GCM

    **connectors/github/page.mdx**: GitHub connector reference.
    - Read `connectors/github/src/index.ts` to extract all actions. For each action, document:
      - Action name (e.g., `issues.list`)
      - Description (from action.description)
      - Required and optional parameters (from action.params)
      - Example CLI usage: `feelr run github issues.list repo=owner/repo`
      - Example curl: `curl https://api.feelr.dev/v1/github/issues.list?repo=owner/repo -H "X-Feelr-Key: fk_..."`

    **connectors/slack/page.mdx**: Same pattern as GitHub but for Slack connector.

    **connectors/stripe/page.mdx**: Same pattern as GitHub but for Stripe connector.

    **connectors/discord/page.mdx**: Same pattern as GitHub but for Discord connector.

    **cli-reference/page.mdx**: CLI command reference.
    - `feelr run <connector> <action> [params...]` -- execute actions
    - `feelr tools [connector [action]]` -- progressive discovery (3 levels)
    - `feelr status [--deep]` -- gateway health
    - `feelr auth <connector>` -- store credentials
    - `feelr chain run|list|validate|show` -- composable actions
    - `feelr init` -- interactive setup wizard
    - Global flags: `--format`, `--verbose`, `--dry-run`
    - Exit codes: 0 (success), 1 (error), 2 (auth required), 3 (not found), 4 (usage error)

    **self-hosting/page.mdx**: Self-hosting guide.
    - Prerequisites: Docker, Docker Compose
    - Quick start: `docker compose up`
    - Configuration: feelr.yaml settings reference (read from self-host/feelr.yaml.template for actual settings)
    - Environment variables: .env file with secrets
    - Architecture: workerd gateway + SQLite + optional Caddy reverse proxy
    - Differences from cloud: billing disabled, local SQLite instead of D1, in-memory rate limiting

    **_meta.ts files**: Create Nextra sidebar metadata for the connectors/ and auth/ subdirectories to control page ordering and titles.
