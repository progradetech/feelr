**init.sh** -- POSIX sh script (not bash) for maximum portability. Per user decision: progressive init, collect admin creds + encryption secret first, then offer optional connector setup.

```sh
#!/bin/sh
# Feelr Self-Hosted Setup
# Generates .env and feelr.yaml for Docker Compose deployment
set -e

echo "=== Feelr Self-Hosted Setup ==="
echo ""
echo "This script generates the configuration files needed to run Feelr."
echo "You'll need Docker and Docker Compose installed."
echo ""

# ---- Step 1: Essential Configuration ----
echo "--- Step 1: Core Configuration (required) ---"
echo ""

# Admin token
printf "Admin token (leave empty to auto-generate): "
read admin_token
if [ -z "$admin_token" ]; then
    admin_token=$(openssl rand -hex 32)
    echo "  Generated: ${admin_token}"
fi

# Encryption key
printf "Encryption key (leave empty to auto-generate): "
read encryption_key
if [ -z "$encryption_key" ]; then
    encryption_key=$(openssl rand -hex 32)
    echo "  Generated: ${encryption_key}"
fi

echo ""
echo "  Core configuration complete."
echo ""

# ---- Step 2: Generate .env ----
cat > .env << ENVEOF
# Feelr Self-Hosted Secrets (generated by init.sh)
FEELR_ADMIN_TOKEN=${admin_token}
FEELR_ENCRYPTION_KEY=${encryption_key}
ENVEOF

# ---- Step 3: Optional Connector Setup ----
echo "--- Step 2: Connector Setup (optional) ---"
echo ""
printf "Configure connectors now? (y/N): "
read configure_connectors

if [ "$configure_connectors" = "y" ] || [ "$configure_connectors" = "Y" ]; then
    echo ""

    # GitHub
    printf "  GitHub Personal Access Token (Enter to skip): "
    read github_pat
    if [ -n "$github_pat" ]; then
        echo "GITHUB_TOKEN=${github_pat}" >> .env
        echo "    GitHub token saved."
    fi

    # Slack (OAuth)
    printf "  Slack Client ID (Enter to skip): "
    read slack_client_id
    if [ -n "$slack_client_id" ]; then
        echo "SLACK_CLIENT_ID=${slack_client_id}" >> .env
        printf "  Slack Client Secret: "
        read slack_client_secret
        echo "SLACK_CLIENT_SECRET=${slack_client_secret}" >> .env
        echo "    Slack OAuth credentials saved."
    fi

    # Discord
    printf "  Discord Bot Token (Enter to skip): "
    read discord_token
    if [ -n "$discord_token" ]; then
        echo "DISCORD_BOT_TOKEN=${discord_token}" >> .env
        echo "    Discord bot token saved."
    fi

    # Stripe
    printf "  Stripe API Key (Enter to skip): "
    read stripe_key
    if [ -n "$stripe_key" ]; then
        echo "STRIPE_API_KEY=${stripe_key}" >> .env
        echo "    Stripe API key saved."
    fi

    echo ""
fi

# ---- Step 4: Generate feelr.yaml ----
if [ ! -f feelr.yaml ]; then
    cp feelr.yaml.template feelr.yaml
    echo "  Generated feelr.yaml from template."
else
    echo "  Existing feelr.yaml found, keeping it."
fi

# ---- Step 5: Copy docker-compose if not present ----
if [ ! -f docker-compose.yml ]; then
    # docker-compose.yml should already be in the self-host directory
    echo "  docker-compose.yml ready."
fi

# ---- Done ----
echo ""
echo "=== Setup Complete ==="
echo ""
echo "Start Feelr:"
echo "  docker compose up -d"
echo ""
echo "With TLS (requires domain pointed at this server):"
echo "  FEELR_DOMAIN=your-domain.com docker compose --profile tls up -d"
echo ""
echo "Dashboard: http://localhost:8080"
echo "API:       http://localhost:8080/v1/"
echo "Health:    http://localhost:8080/health"
echo ""
echo "Admin token: ${admin_token}"
echo "(Save this -- you'll need it for the dashboard and CLI)"
```

Make the script executable in the Dockerfile or via git (the plan executor should `chmod +x self-host/init.sh`).

**README.md** -- Quick-start guide for self-hosted deployment:

```markdown
# Feelr Self-Hosted

Run the complete Feelr stack on your own infrastructure.

## Quick Start

1. Clone and navigate to self-host directory:
   ```
   git clone https://github.com/andrewprograde/feelr.git
   cd feelr/self-host
   ```

2. Run the setup script:
   ```
   ./init.sh
   ```

3. Start Feelr:
   ```
   docker compose up -d
   ```

4. Verify:
   ```
   curl http://localhost:8080/health
   ```

## What's Included

- **Gateway API** on port 8080 (workerd runtime)
- **Dashboard** at http://localhost:8080 (static Next.js)
- **SQLite storage** for API keys, credentials, and usage data
- **Rate limiting** with configurable tiers

## Configuration

### feelr.yaml

All settings are in `feelr.yaml`. The file is generated with comments explaining each option.

Key settings:
- `rate_limits` - Customize request limits per API key tier
- `billing.enabled` - Enable Stripe billing for internal chargeback (disabled by default)
- `encryption.enabled` - AES-256-GCM for stored credentials (enabled by default)
- `storage.auto_migrate` - Auto-run schema migrations on startup (enabled by default)

### .env

Secrets are stored in `.env`:
- `FEELR_ADMIN_TOKEN` - Required for dashboard access and key management
- `FEELR_ENCRYPTION_KEY` - Required for credential encryption
- Connector tokens (optional): `GITHUB_TOKEN`, `SLACK_CLIENT_ID`, etc.

### TLS with Caddy

For production deployments with automatic HTTPS:

```
FEELR_DOMAIN=api.example.com docker compose --profile tls up -d
```

Caddy automatically obtains and renews Let's Encrypt certificates.

## Data

All data is stored in the `feelr-data` Docker volume at `/data/feelr/`:
- `do/` - Durable Object storage (API keys, credentials, usage data)

### Backup

```
docker compose stop
docker cp $(docker compose ps -q feelr):/data/feelr ./backup
docker compose start
```

## Feature Parity

Self-hosted Feelr has the same features as the cloud version except:
- Billing is disabled by default (can be enabled for internal use)
- Rate limits are configurable (cloud uses fixed tiers)
- Single-instance deployment (cloud is globally distributed)

## Troubleshooting

**Container won't start:**
```
docker compose logs feelr
```

**Reset everything:**
```
docker compose down -v
./init.sh
docker compose up -d
