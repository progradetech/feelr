**feelr.yaml.template** -- a fully commented YAML config file that serves as both template and documentation. Include ALL configurable settings with sensible defaults and explanatory comments:

```yaml
# Feelr Self-Hosted Configuration
# Generated by: ./init.sh
# Documentation: https://feelr.dev/docs/self-hosting

# Runtime mode (do not change)
runtime: self-hosted

# Gateway settings
gateway:
  # Port the gateway listens on inside the container
  # External port is configured in docker-compose.yml
  port: 8080

# Billing configuration
# Disabled by default for self-hosted deployments.
# Enable and connect your own Stripe for internal chargeback use cases.
billing:
  enabled: false
  # stripe_secret_key: sk_...  # Set in .env as STRIPE_SECRET_KEY instead

# Encryption configuration
# AES-256-GCM encryption for stored credentials.
# Enabled by default -- disable only for local-only dev instances.
encryption:
  enabled: true
  # The encryption key is stored in .env as FEELR_ENCRYPTION_KEY

# Rate limiting configuration
# Define requests-per-minute limits for each API key tier.
# Self-hosters can customize these based on their infrastructure capacity.
rate_limits:
  free:
    requests_per_minute: 30
  pro:
    requests_per_minute: 300
  enterprise:
    requests_per_minute: 3000
  # IP-based pre-auth defense (requests per 10 seconds)
  ip:
    requests_per_10s: 100

# Storage configuration
# SQLite databases are split by concern for better concurrency and backup.
storage:
  # Base directory for all data files (inside container)
  data_dir: /data/feelr
  # Auto-run schema migrations on startup
  # Set FEELR_AUTO_MIGRATE=false in .env to disable
  auto_migrate: true

# Data retention
# Usage analytics and rate limit events older than this are cleaned up daily.
retention:
  days: 90

# Logging
logging:
  # Log level: debug, info, warn, error
  level: info
```

**env.template** -- template for secrets:

```
# Feelr Self-Hosted Secrets
# Copy to .env and fill in values (or run ./init.sh to generate)

# Required: Admin token for dashboard and API key management
# Generate with: openssl rand -hex 32
FEELR_ADMIN_TOKEN=

# Required: Encryption key for credential storage (AES-256-GCM)
# Generate with: openssl rand -hex 32
FEELR_ENCRYPTION_KEY=

# Optional: Connector tokens (configure via dashboard or CLI after setup)
# GITHUB_TOKEN=ghp_...
# SLACK_CLIENT_ID=
# SLACK_CLIENT_SECRET=
# DISCORD_BOT_TOKEN=
# STRIPE_API_KEY=sk_...

# Optional: Override auto-migration (default: true from feelr.yaml)
# FEELR_AUTO_MIGRATE=false

# Optional: Override port (default: 8080)
# FEELR_PORT=8080
```

Ensure the YAML template has proper indentation and all comments are clear and actionable.

Create `apps/gateway/src/runtime/config.ts` with TypeScript types and a config loader.

**FeelrYamlConfig** type -- matches the YAML structure exactly:
```typescript
export interface FeelrYamlConfig {
  runtime: 'cloud' | 'self-hosted'
  gateway: { port: number }
  billing: { enabled: boolean }
  encryption: { enabled: boolean }
  rate_limits: {
    free: { requests_per_minute: number }
    pro: { requests_per_minute: number }
    enterprise: { requests_per_minute: number }
    ip: { requests_per_10s: number }
  }
  storage: {
    data_dir: string
    auto_migrate: boolean
  }
  retention: { days: number }
  logging: { level: 'debug' | 'info' | 'warn' | 'error' }
}
```

**DEFAULT_CONFIG** -- sensible defaults matching the YAML template:
```typescript
export const DEFAULT_CONFIG: FeelrYamlConfig = {
  runtime: 'self-hosted',
  gateway: { port: 8080 },
  billing: { enabled: false },
  encryption: { enabled: true },
  rate_limits: {
    free: { requests_per_minute: 30 },
    pro: { requests_per_minute: 300 },
    enterprise: { requests_per_minute: 3000 },
    ip: { requests_per_10s: 100 },
  },
  storage: { data_dir: '/data/feelr', auto_migrate: true },
  retention: { days: 90 },
  logging: { level: 'info' },
}
```

**loadConfig(yamlText: string): FeelrYamlConfig** -- parses YAML text and deep-merges with defaults. Use a simple hand-rolled YAML parser that handles the flat structure (no dependency on js-yaml since this runs in workerd where Node modules aren't available). The YAML structure is simple enough (no anchors, no complex types) that a basic line-by-line parser works:
- Lines starting with `#` are comments (skip)
- Lines with `key: value` at root level or indented
- Support nested keys via indentation tracking

Alternatively, since the config is loaded once at startup, accept a JSON-parsed config object and export `loadConfigFromObject(obj: Record<string, unknown>): FeelrYamlConfig` that deep-merges with defaults. The YAML-to-JSON conversion can happen outside workerd (in the init script or Docker entrypoint).

Export `FeelrYamlConfig`, `DEFAULT_CONFIG`, and the loader function.

**Environment variable overrides:** The loader should check for env var overrides:
- `FEELR_AUTO_MIGRATE` overrides `storage.auto_migrate`
- `FEELR_PORT` overrides `gateway.port`
- These are read from the workerd bindings, not process.env (workerd doesn't have process.env)
