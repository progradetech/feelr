  <name>Task 1: Install Gitleaks and run initial audit scans</name>
  <files>.gitleaks.toml</files>
  <action>
1. Install Gitleaks via Go:
   ```bash
   go install github.com/gitleaks/gitleaks/v8@latest
   ```
   Verify installation: `gitleaks version`

2. Run git history scan (AUDIT-01 — full history audit):
   ```bash
   gitleaks git -v --report-format json --report-path /tmp/gitleaks-history.json .
   ```
   This scans all 366 commits for leaked secrets. Capture and document every finding.

3. Run git history audit for env files specifically:
   ```bash
   git log --all --oneline -- '*.env*'
   ```
   Expected: No results (research confirmed self-host/.env was never tracked).

4. Run directory scan (current HEAD snapshot):
   ```bash
   gitleaks dir -v --report-format json --report-path /tmp/gitleaks-snapshot.json .
   ```
   This scans the working tree as it would appear in the public repo snapshot.

5. Analyze both reports. For EACH finding, document:
   - File path and line number
   - Rule that triggered (e.g., `github-pat`, `stripe-api-key`, `generic-api-key`)
   - The matched string (redacted if needed)
   - Classification: `false-positive` (doc example, test fixture, placeholder) or `real-secret` (must be removed/rotated)
   - Reason for classification

Research predicts 10-30 false positives from documentation examples and test fixtures, zero real secrets. Known false positive sources:
   - `connectors/github/src/__tests__/actions.test.ts` — `ghp_test_token`
   - `connectors/github/src/__tests__/github-fetch.test.ts` — `ghp_test123`
   - `apps/gateway/src/__tests__/credentials.test.ts` — `ghp_test_token_123456`, `xoxb-slack-token`, `sk_test_stripe`
   - `apps/gateway/src/__tests__/crypto.test.ts` — `ghp_abc123def456`
   - `apps/docs/app/docs/connectors/github/page.mdx` — `ghp_your_pat_here`
   - `apps/docs/app/docs/connectors/stripe/page.mdx` — `sk_test_your_stripe_key`
   - `apps/docs/app/docs/auth/setup/page.mdx` — `ghp_your_pat_here`, `sk_live_your_stripe_key`
   - `apps/docs/app/docs/getting-started-api/page.mdx` — `ghp_your_github_pat_here`
   - `README.md` — `ghp_...`
   - `self-host/env.template` — `GITHUB_TOKEN=ghp_...`
   - `cli/cmd/auth.go` — `sk_live_*`, `sk_test_*`
   - `cli/internal/auth/providers.go` — `sk_live_*`, `sk_test_*`
   - `feelr-strategy.md` — `ghp_xxxx`

If ANY real secret is found, STOP and report it. Do NOT proceed to allowlisting real secrets.

6. Create `.gitleaks.toml` at repo root with allowlist entries for every confirmed false positive. Use the structure from research:

```toml
# .gitleaks.toml - Feelr secret scanning configuration
# All entries are documented false positives from tests, docs, and examples.

[extend]
useDefault = true

# Allowlist: test fixtures and documentation examples
[[allowlists]]
description = "Test fixture tokens in unit tests"
paths = [
  '''connectors/.*/src/__tests__/''',
  '''apps/gateway/src/__tests__/''',
]

[[allowlists]]
description = "Documentation example tokens and placeholders"
paths = [
  '''apps/docs/''',
  '''README\.md$''',
  '''CONTRIBUTING\.md$''',
  '''self-host/env\.template$''',
  '''self-host/init\.sh$''',
]

[[allowlists]]
description = "CLI help text with example token patterns"
paths = [
  '''cli/cmd/auth\.go$''',
  '''cli/internal/auth/providers\.go$''',
]

[[allowlists]]
description = "Internal planning and strategy docs (excluded from public repo)"
paths = [
  '''\.planning/''',
  '''feelr-strategy\.md$''',
  '''docs/deployment/''',
]
```

Adjust the allowlist based on ACTUAL scan findings — do not blindly copy the template. Add or remove path patterns and regex patterns as needed to cover exactly the findings encountered. Each allowlist entry must correspond to actual false positives found in the scan.

7. Verify the allowlist works by re-running:
   ```bash
   gitleaks dir -v --config=.gitleaks.toml --report-format json --report-path /tmp/gitleaks-allowlisted.json .
   ```
   If any findings remain, analyze and either add to allowlist (if false positive) or flag as real secret.
