  <action>
    Create 10 action handler files. Every action follows the same pattern:
    1. Import `ActionDefinition`, `ActionContext`, `ActionResult` from `@feelr/connector-sdk`
    2. Import `FeelrError` from `@feelr/connector-sdk`
    3. Import `githubFetch` from `../github-fetch`
    4. Import the appropriate flatten function from `../flatten`
    5. Export a named `ActionDefinition` constant

    **Each handler MUST:**
    - Check `ctx.credential` first -- throw `AUTH_REQUIRED` (401, hint: auth) if missing
    - Parse `repo` param in "owner/repo" format (split on `/`, throw `VALIDATION_ERROR` 400 abort if invalid) -- except `repos.list` which has no repo param
    - Call `githubFetch` with the correct path, method, body, and params
    - Use `ctx.cursor` (not ctx.params.cursor) for pagination
    - Flatten response using the appropriate flatten function
    - Return `ActionResult` with `data`, `meta` (cursor/has_more for list actions), and `raw`

    **Shared credential check helper** -- add at top of each file or create a tiny shared helper:
    ```typescript
    function requireCredential(ctx: ActionContext): string {
      if (!ctx.credential) {
        throw new FeelrError('AUTH_REQUIRED', {
          message: 'No GitHub credential stored. Store a PAT via admin API first.',
          hint: 'auth',
          status: 401,
        })
      }
      return ctx.credential
    }
    ```

    **Shared repo parse helper** -- add to each file that needs it or create a shared util:
    ```typescript
    function parseRepo(repo: unknown): [string, string] {
      const str = String(repo ?? '')
      const [owner, name] = str.split('/')
      if (!owner || !name) {
        throw new FeelrError('VALIDATION_ERROR', {
          message: 'repo must be in "owner/repo" format',
          hint: 'abort',
          status: 400,
        })
      }
      return [owner, name]
    }
    ```
    Best approach: Create a small `connectors/github/src/utils.ts` with both helpers to avoid duplication across 10 files. Import in each action.

    **Action specifications:**

    **issues-list.ts** (`issuesList`):
    - Params: `repo` (string, required), `state` (string, optional, default: "open"), `labels` (string, optional), `sort` (string, optional, default: "created"), `per_page` (number, optional, default: 30)
    - GET `/repos/{owner}/{repo}/issues`
    - Query params: state, labels, sort, per_page, page (from ctx.cursor)
    - CRITICAL: Filter out items that have a `pull_request` key (GitHub issues endpoint returns PRs too)
    - Flatten each item with `flattenIssue`
    - Returns: list
    - Description: ~60-80 tokens, mention params, mention flat response fields

    **issues-get.ts** (`issuesGet`):
    - Params: `repo` (string, required), `issue_number` (number, required)
    - GET `/repos/{owner}/{repo}/issues/{issue_number}`
    - Flatten with `flattenIssue`
    - Returns: single

    **issues-create.ts** (`issuesCreate`):
    - Params: `repo` (string, required), `title` (string, required), `body` (string, optional), `labels` (string, optional -- comma-separated, split into array for GitHub API body), `assignees` (string, optional -- comma-separated, split into array)
    - POST `/repos/{owner}/{repo}/issues`
    - Body: `{ title, body?, labels?: string[], assignees?: string[] }`
    - Flatten response with `flattenIssue`
    - Returns: single

    **issues-update.ts** (`issuesUpdate`):
    - Params: `repo` (string, required), `issue_number` (number, required), `title` (string, optional), `body` (string, optional), `state` (string, optional -- "open"/"closed"), `labels` (string, optional -- comma-separated), `assignees` (string, optional -- comma-separated)
    - PATCH `/repos/{owner}/{repo}/issues/{issue_number}`
    - Body: only include fields that were provided (don't send undefined fields)
    - Flatten response with `flattenIssue`
    - Returns: single

    **issues-close.ts** (`issuesClose`):
    - Params: `repo` (string, required), `issue_number` (number, required), `state_reason` (string, optional, default: "completed")
    - PATCH `/repos/{owner}/{repo}/issues/{issue_number}`
    - Body: `{ state: "closed", state_reason }` -- always sets state to "closed"
    - Flatten response with `flattenIssue`
    - Returns: single

    **pulls-list.ts** (`pullsList`):
    - Params: `repo` (string, required), `state` (string, optional, default: "open"), `sort` (string, optional, default: "created"), `per_page` (number, optional, default: 30)
    - GET `/repos/{owner}/{repo}/pulls`
    - Query params: state, sort, per_page, page (from ctx.cursor)
    - Flatten each item with `flattenPullRequest`
    - Returns: list

    **pulls-get.ts** (`pullsGet`):
    - Params: `repo` (string, required), `pull_number` (number, required)
    - GET `/repos/{owner}/{repo}/pulls/{pull_number}`
    - Flatten with `flattenPullRequest`
    - Returns: single

    **pulls-create.ts** (`pullsCreate`):
    - Params: `repo` (string, required), `title` (string, required), `head` (string, required), `base` (string, required), `body` (string, optional), `draft` (boolean, optional)
    - POST `/repos/{owner}/{repo}/pulls`
    - Body: `{ title, head, base, body?, draft? }`
    - Flatten response with `flattenPullRequest`
    - Returns: single

    **pulls-merge.ts** (`pullsMerge`):
    - Params: `repo` (string, required), `pull_number` (number, required), `merge_method` (string, optional, default: "merge"), `commit_title` (string, optional), `commit_message` (string, optional)
    - PUT `/repos/{owner}/{repo}/pulls/{pull_number}/merge`
    - Body: `{ merge_method, commit_title?, commit_message? }`
    - Note: GitHub returns 204 on successful merge or `{ sha, merged, message }` -- handle both. Return `{ merged: true, sha, message }` as flattened data (no flattenPullRequest needed for merge response).
    - Returns: single

    **repos-list.ts** (`reposList`):
    - Params: `type` (string, optional, default: "all"), `sort` (string, optional, default: "created"), `per_page` (number, optional, default: 30)
    - GET `/user/repos` (no owner/repo -- lists authenticated user's repos)
    - NO repo param -- do NOT call parseRepo
    - Query params: type, sort, per_page, page (from ctx.cursor)
    - Flatten each item with `flattenRepository`
    - Returns: list

    **Agent-optimized descriptions:** Each action's `description` should be 50-100 tokens covering: what it does, required params, key optional params, and what fields are in the flat response. Example format:
    "Lists issues for a repository. Requires repo (owner/repo format). Optional: state (open/closed/all), labels (comma-separated), sort (created/updated/comments), per_page. Returns [{id, number, state, title, user_login, labels, created_at, ...}]."
