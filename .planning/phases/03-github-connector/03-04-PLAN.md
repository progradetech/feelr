    **github-fetch.test.ts:**

    Test the `githubFetch` function with a mocked `fetch` function. Create a helper that returns mock `Response` objects with configurable status, headers, and body.

    Test cases:
    1. **Successful GET request:** Mock 200 response with JSON body and rate limit headers. Verify:
       - Correct URL construction with path and query params
       - Authorization, Accept, X-GitHub-Api-Version, User-Agent headers sent
       - Response data parsed correctly
       - Rate limit extracted from headers (remaining, limit, used, reset)

    2. **Pagination parsing:** Mock 200 response with Link header containing `rel="next"`. Verify:
       - `pagination.hasMore` is true
       - `pagination.nextPage` is the correct page number
       - When no Link header, `hasMore` is false

    3. **POST with body:** Mock 201 response. Verify:
       - Method is POST
       - Content-Type: application/json header sent
       - Body serialized as JSON

    4. **204 No Content (merge):** Mock 204 response. Verify:
       - Returns empty object as data (no JSON parse attempt)

    5. **Error mapping -- 401:** Mock 401 response. Verify:
       - Throws FeelrError with code `AUTH_INVALID`, hint `auth`, status 401

    6. **Error mapping -- 403 (rate limit):** Mock 403 response with `x-ratelimit-remaining: 0`. Verify:
       - Throws FeelrError with code `RATE_LIMITED`, hint `retry`, status 429

    7. **Error mapping -- 403 (permission):** Mock 403 response with `x-ratelimit-remaining: 4999`. Verify:
       - Throws FeelrError with code `FORBIDDEN`, hint `auth`, status 403
       - Detail mentions PAT scope

    8. **Error mapping -- 404:** Mock 404 response. Verify:
       - Throws FeelrError with code `NOT_FOUND`, hint `abort`, status 404
       - Detail mentions GitHub 404 ambiguity

    9. **Error mapping -- 422 (validation):** Mock 422 response with GitHub `errors` array (`[{ resource: "Issue", field: "title", code: "missing_field" }]`). Verify:
       - Throws FeelrError with code `VALIDATION_ERROR`, hint `abort`, status 400
       - Detail contains the errors array as JSON string (locked decision: forward validation errors)

    10. **Error mapping -- 429:** Mock 429 response with Retry-After header. Verify:
        - Throws FeelrError with code `RATE_LIMITED`, hint `retry`, status 429

    11. **Error mapping -- 500:** Mock 500 response. Verify:
        - Throws FeelrError with code `UPSTREAM_ERROR`, hint `retry`, status 502

    12. **Query params skip undefined/empty values:** Pass params with undefined and empty string values. Verify they are not included in the URL.

    **flatten.test.ts:**

    Test each flatten function with realistic sample GitHub API response objects.

    1. **flattenIssue:** Provide a full GitHub issue object (nested user, labels array, assignee, etc.). Verify:
       - Returns exactly 13 keys
       - `user_login` extracted from `user.login`
       - `assignee_login` extracted from `assignee.login`
       - `labels` is array of name strings (not full label objects)
       - Nullable fields (`state_reason`, `assignee_login`, `closed_at`) return null when absent

    2. **flattenPullRequest:** Provide a full GitHub PR object. Verify:
       - Returns exactly 15 keys
       - `head_ref` from `head.ref`, `head_sha` from `head.sha`, `base_ref` from `base.ref`
       - `merged` is boolean
       - `labels` is array of name strings

    3. **flattenRepository:** Provide a full GitHub repo object. Verify:
       - Returns exactly 12 keys
       - Nullable fields (`description`, `language`) handled correctly
       - Numeric fields (`stargazers_count`, `forks_count`) passed through

    4. **Edge cases:** Missing nested objects (user is null), empty labels array, all nullable fields absent.
