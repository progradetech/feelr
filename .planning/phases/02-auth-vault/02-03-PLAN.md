Create `apps/gateway/src/durable-objects/token-coordinator.ts`:

This is a SQLite-backed Durable Object that extends the `DurableObject` base class (modern pattern per research -- use `extends DurableObject<Env>` not the old constructor pattern). The DO uses RPC methods (not fetch handler) as the primary interface.

**Import:** `import { DurableObject } from 'cloudflare:workers'`

**Env type for DO:** Define a local `Env` interface matching the wrangler bindings that the DO needs access to. At minimum it needs `AUTH_KV: KVNamespace` and `ENCRYPTION_KEY: string` for write-through to KV after refresh. Use the bindings from the AppEnv type but since DO can't import Hono types directly, define a minimal interface:

```typescript
interface Env {
  AUTH_KV: KVNamespace
  ENCRYPTION_KEY: string
}
```

**Constructor:**
- Call `super(ctx, env)`
- Use `ctx.blockConcurrencyWhile()` to initialize the SQLite schema on first instantiation:

```sql
CREATE TABLE IF NOT EXISTS tokens (
  connector TEXT PRIMARY KEY,
  access_token TEXT NOT NULL,
  refresh_token TEXT NOT NULL,
  expires_at INTEGER NOT NULL,
  status TEXT NOT NULL DEFAULT 'active',
  retry_count INTEGER NOT NULL DEFAULT 0,
  last_refresh_at INTEGER,
  created_at INTEGER NOT NULL DEFAULT (unixepoch() * 1000),
  updated_at INTEGER NOT NULL DEFAULT (unixepoch() * 1000)
)
```

**RPC Methods (public, called by Workers via stub):**

1. **`async storeCredential(connector: string, accessToken: string, refreshToken: string, expiresAt: number): Promise<void>`**
   - INSERT OR REPLACE into tokens table
   - Set status='active', retry_count=0, updated_at=Date.now()
   - Call `scheduleNextRefresh()` to set alarm for proactive refresh
   - Note: accessToken and refreshToken are ALREADY encrypted when passed in -- the DO stores them as-is

2. **`async getCredential(connector: string): Promise<TokenState | null>`**
   - SELECT from tokens WHERE connector = ?
   - If not found, return null
   - If found and within 5-minute expiry buffer AND status is 'active', call `scheduleRefresh(connector)` to trigger proactive refresh via alarm
   - Return the token state (status, encrypted tokens, expiresAt, etc.)
   - The returned `accessToken` is still encrypted -- the caller decrypts it

3. **`async removeCredential(connector: string): Promise<void>`**
   - DELETE FROM tokens WHERE connector = ?
   - Call `scheduleNextRefresh()` to recalculate alarm for remaining tokens

4. **`async listCredentials(): Promise<Array<{ connector: string, status: string, expiresAt: number }>>`**
   - SELECT connector, status, expires_at FROM tokens
   - Returns summary without encrypted token values (for admin listing)

**Private Methods:**

5. **`private async scheduleNextRefresh(): Promise<void>`**
   - Find the earliest expiring active token with a non-null refresh_token:
     `SELECT MIN(expires_at) as earliest FROM tokens WHERE status = 'active' AND refresh_token != ''`
   - If found, set alarm for `earliest - 5 * 60 * 1000` (5 minutes before expiry)
   - Clamp to at least `Date.now() + 1000` (1 second from now minimum)
   - If no tokens need refresh, don't set alarm (or delete existing alarm)

6. **`private async scheduleRefresh(connector: string): Promise<void>`**
   - Set alarm for near-immediate execution (Date.now() + 100ms)
   - This triggers the alarm handler which will check and refresh the specific token

**Alarm Handler:**

7. **`async alarm(): Promise<void>`**
   - Select all tokens approaching expiry:
     ```sql
     SELECT * FROM tokens
     WHERE status = 'active'
       AND expires_at - ? < ?
       AND refresh_token != ''
     ```
     Parameters: `Date.now()`, `5 * 60 * 1000` (5-minute buffer)
   - For each approaching-expiry token, call `performRefresh(token)`
   - After processing, call `scheduleNextRefresh()` to set alarm for next batch

8. **`private async performRefresh(token: TokenRow): Promise<void>`**
   - If `token.retry_count >= 3`:
     - Set status = 'failed', update updated_at
     - Log: `console.log(JSON.stringify({ event: 'token_refresh_exhausted', connector: token.connector }))`
     - Return (stop retrying)
   - Set status = 'refreshing', update updated_at
   - **IMPORTANT: Actual refresh is a STUB for Phase 2.** The real refresh requires connector-specific OAuth endpoints which are built in Phase 3/5. For now:
     - Log: `console.log(JSON.stringify({ event: 'token_refresh_stub', connector: token.connector, message: 'Actual refresh not implemented until connector phase' }))`
     - Set status back to 'active', DO NOT increment retry_count for stub
     - This preserves the scheduling and retry infrastructure while deferring the actual OAuth call
   - In the future (Phase 3/5), `performRefresh` will:
     - Call the connector's refresh endpoint with the decrypted refresh token
     - On success: update access_token, refresh_token, expires_at, status='active', retry_count=0
     - On failure: increment retry_count, set status='active', schedule retry with exponential backoff (2^retryCount * 1000 ms)

**TokenRow type** (internal to DO, maps to SQL row):
```typescript
interface TokenRow {
  connector: string
  access_token: string
  refresh_token: string
  expires_at: number
  status: string
  retry_count: number
  last_refresh_at: number | null
  created_at: number
  updated_at: number
}
```

Import `TokenState` from `'../auth/types'` -- or define locally if the import path causes issues in the DO context (DO files are loaded by wrangler separately). Prefer the import if it works; otherwise duplicate the type definition with a comment pointing to the canonical source.

**SQL query pattern:** Use `this.ctx.storage.sql.exec(query, ...params)` for all database operations. Use `.toArray()` for multiple rows and `.one()` for single-row queries. Results are returned as plain objects with column names matching the SQL schema (snake_case).
