  <name>Task 1: Create crypto module with HKDF key derivation and AES-256-GCM encrypt/decrypt</name>
  <files>apps/gateway/src/auth/crypto.ts</files>
  <action>
Create `apps/gateway/src/auth/crypto.ts` with the following exports:

1. **`encrypt(plaintext: string, masterSecret: string, purpose?: string): Promise<string>`**
   - Derive an AES-256-GCM key from `masterSecret` using HKDF with SHA-256
   - HKDF salt: static `new TextEncoder().encode('feelr-credential-encryption-v1')` (hardcoded, not secret)
   - HKDF info: `purpose` parameter (default: `'credential'`) for domain separation
   - Generate 12-byte random IV via `crypto.getRandomValues(new Uint8Array(12))`
   - Encrypt plaintext with AES-256-GCM
   - Pack result as: IV (12 bytes) + ciphertext (includes 16-byte auth tag)
   - Return base64-encoded packed bytes using `btoa(String.fromCharCode(...packed))`

2. **`decrypt(encoded: string, masterSecret: string, purpose?: string): Promise<string>`**
   - Derive same key using HKDF (same salt, same info)
   - Decode base64: `Uint8Array.from(atob(encoded), c => c.charCodeAt(0))`
   - Unpack: first 12 bytes = IV, rest = ciphertext
   - Decrypt with AES-256-GCM
   - Return plaintext string

3. **`hashToken(token: string): Promise<string>`**
   - SHA-256 hash the token via `crypto.subtle.digest('SHA-256', encoded)`
   - Return lowercase hex string

Internal helper (not exported):
- `deriveKey(masterSecret: string, info: string): Promise<CryptoKey>` -- HKDF derivation

Use HKDF (not PBKDF2) because the master secret is a Worker Secret (already high-entropy). PBKDF2's 100K+ iterations would be wasted cycles. HKDF is a single-pass extraction.

Do NOT import any external crypto libraries. Everything uses the Workers-native Web Crypto API (`crypto.subtle`).
  </action>

  </verify>
