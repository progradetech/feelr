**1. Create `apps/gateway/src/middleware/admin-auth.ts`:**

Admin token validation middleware. Uses timing-safe comparison to prevent timing attacks.

```typescript
import { createMiddleware } from 'hono/factory'
import type { AppEnv } from '../lib/types'
import { FeelrError } from '../lib/errors'

export const adminAuthMiddleware = createMiddleware<AppEnv>(async (c, next) => {
  const authHeader = c.req.header('Authorization')
  if (!authHeader?.startsWith('Bearer ')) {
    throw new FeelrError('ADMIN_AUTH_REQUIRED', {
      message: 'Admin token required. Include Authorization: Bearer <token> header.',
      hint: 'auth',
      status: 401,
    })
  }

  const token = authHeader.slice(7) // Remove 'Bearer ' prefix
  const expected = c.env.ADMIN_TOKEN

  // Timing-safe comparison
  const encoder = new TextEncoder()
  const a = encoder.encode(token)
  const b = encoder.encode(expected)

  if (a.byteLength !== b.byteLength || !crypto.subtle.timingSafeEqual(a, b)) {
    throw new FeelrError('ADMIN_AUTH_INVALID', {
      message: 'Invalid admin token.',
      hint: 'auth',
      status: 403,
    })
  }

  await next()
})
```

Note: If byteLength differs, we still throw ADMIN_AUTH_INVALID (not a different error) to avoid leaking information about token length.

**2. Create `apps/gateway/src/auth/credentials.ts`:**

Credential management functions. Handles encryption/decryption and coordinates with both KV (fast reads) and DO (refresh coordination).

```typescript
import { encrypt, decrypt } from './crypto'
import type { CredentialRecord } from './types'

/**
 * Store encrypted credentials in KV and register with DO coordinator.
 * Credentials are encrypted BEFORE storage -- KV only ever sees ciphertext.
 */
export async function storeCredential(
  connector: string,
  credential: CredentialRecord,
  kv: KVNamespace,
  encryptionKey: string,
  tokenCoordinator?: DurableObjectStub  // optional: only if token has expiry + refresh
): Promise<void> {
  // Encrypt the entire credential payload
  const plaintext = JSON.stringify(credential)
  const encrypted = await encrypt(plaintext, encryptionKey)

  // Store encrypted credential in KV for fast global reads
  await kv.put(`cred:${connector}`, encrypted)

  // If token is refreshable (has both refresh_token and expires_at),
  // register with DO coordinator for proactive refresh scheduling
  if (tokenCoordinator && credential.refreshToken && credential.expiresAt) {
    // Pass encrypted tokens to DO -- the DO stores them as-is
    const encryptedAccess = await encrypt(credential.accessToken, encryptionKey)
    const encryptedRefresh = await encrypt(credential.refreshToken, encryptionKey)
    await tokenCoordinator.storeCredential(
      connector,
      encryptedAccess,
      encryptedRefresh,
      credential.expiresAt
    )
  }
}

/**
 * Retrieve and decrypt credentials for a connector.
 * Reads from KV (globally cached, fast).
 */
export async function getCredential(
  connector: string,
  kv: KVNamespace,
  encryptionKey: string
): Promise<CredentialRecord | null> {
  const encrypted = await kv.get(`cred:${connector}`)
  if (!encrypted) return null

  const plaintext = await decrypt(encrypted, encryptionKey)
  return JSON.parse(plaintext) as CredentialRecord
}

/**
 * Remove credentials for a connector from both KV and DO.
 */
export async function removeCredential(
  connector: string,
  kv: KVNamespace,
  tokenCoordinator?: DurableObjectStub
): Promise<void> {
  await kv.delete(`cred:${connector}`)
  if (tokenCoordinator) {
    await tokenCoordinator.removeCredential(connector)
  }
}

/**
 * List all stored credentials (connector names + status only, no tokens).
 * Uses KV list with prefix to find all credential keys.
 */
export async function listCredentials(
  kv: KVNamespace
): Promise<Array<{ connector: string }>> {
  const list = await kv.list({ prefix: 'cred:' })
  return list.keys.map(k => ({
    connector: k.name.replace('cred:', ''),
  }))
}
```

The `tokenCoordinator` parameter uses `DurableObjectStub` type. If TypeScript has issues with the RPC method types on the generic stub, cast it to `any` for the method calls with a TODO comment to improve typing when the DO RPC type pattern is established. Alternatively, define a `TokenCoordinatorStub` interface locally that declares the expected RPC methods.

Best approach: Define a small interface for the stub's RPC methods to maintain type safety:

```typescript
/** Type-safe interface for TokenCoordinator RPC calls */
interface TokenCoordinatorRpc {
  storeCredential(connector: string, accessToken: string, refreshToken: string, expiresAt: number): Promise<void>
  removeCredential(connector: string): Promise<void>
  getCredential(connector: string): Promise<TokenState | null>
  listCredentials(): Promise<Array<{ connector: string, status: string, expiresAt: number }>>
}
```

Use this for parameter types instead of raw `DurableObjectStub`.

**3. Update `apps/gateway/src/routes/v1.ts`:**

Wire credential retrieval into the connector dispatch pipeline. Before calling the action handler, look up the credential for the requested connector and pass it via `ActionContext.credential`.

In the existing `v1.all('/:connector/:action', ...)` handler, AFTER the action lookup and BEFORE the handler call, add:

```typescript
// Retrieve decrypted credential for this connector (if stored)
import { getCredential } from '../auth/credentials'

// ... inside the handler:
let credential: string | undefined

try {
  const credRecord = await getCredential(connectorName, c.env.AUTH_KV, c.env.ENCRYPTION_KEY)
  if (credRecord) {
    credential = credRecord.accessToken
  }
} catch {
  // Credential retrieval failed -- proceed without credential
  // Connector may not require auth (e.g., public APIs)
}

// Execute action handler with credential
const result = await action.handler({
  params: actionParams,
  fetch: fetch,
  credential,  // This was previously undefined in Phase 1
})
```

This wiring means:
- If a credential exists for the connector, it's decrypted and passed to the handler
- If no credential exists, `credential` is `undefined` (same as Phase 1 behavior)
- Connectors that require auth can check for `credential` presence and throw `AUTH_REQUIRED` if missing
- The existing mock connector doesn't use `credential`, so this is backward-compatible

Also: check the credential status via the DO if the credential has an expiry. If the DO reports status='failed', throw a FeelrError with code CREDENTIAL_EXPIRED. This provides clear feedback to the user:

```typescript
if (credRecord && credRecord.expiresAt) {
  const doId = c.env.TOKEN_COORDINATOR.idFromName('default')
  const doStub = c.env.TOKEN_COORDINATOR.get(doId)
  const tokenState = await doStub.getCredential(connectorName)
  if (tokenState && tokenState.status === 'failed') {
    throw new FeelrError('CREDENTIAL_EXPIRED', {
      message: `Credential for "${connectorName}" has expired and refresh failed. Store new credentials via admin API.`,
      hint: 'auth',
      status: 401,
    })
  }
}
```

However, this adds a DO round-trip on every request. For Phase 2, this is acceptable (single-user, low traffic). In production hardening, we could cache the status in KV or use a lighter check. Alternatively, only check DO status if the credential is close to expiry (expiresAt - Date.now() < 10 minutes). Use the simpler approach for now: always check DO status when the credential has an expiresAt.

Actually -- the simpler approach is: just read from KV and trust that the DO's proactive refresh has already updated KV. If the credential works, great. If the upstream returns 401, the error bubbles as UPSTREAM_ERROR. The DO check is an optimization we can add later. For Phase 2, skip the DO round-trip in the dispatch path and rely on proactive refresh keeping KV fresh.

**Go with the simpler approach:** Just read credential from KV, decrypt it, pass to handler. No DO round-trip in the request path. The DO handles refresh in the background via alarms. This keeps latency low and aligns with the architecture pattern from research ("read from KV for speed, write through DO for consistency").
