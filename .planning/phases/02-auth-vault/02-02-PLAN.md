**1. Create `apps/gateway/src/auth/keys.ts`:**

Key management functions using Web Crypto API. No external dependencies.

**Key format:** `fk_<env>_<shortToken>_<longToken>`
- `fk` = "Feelr Key" prefix (enables GitHub secret scanning detection)
- `env` = `live` or `test` (from ENVIRONMENT binding, mapped: "production" -> "live", everything else -> "test")
- `shortToken` = 8 chars base62 (for identification in dashboards/logs)
- `longToken` = 32 chars base62 (the secret, SHA-256 hashed for storage)

Exports:

```typescript
import type { ApiKeyRecord, ParsedApiKey } from './types'
import { hashToken } from './crypto'

// Base62 character set for random token generation
const BASE62 = 'ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789'

function generateRandomBase62(byteLength: number): string {
  const bytes = crypto.getRandomValues(new Uint8Array(byteLength))
  return Array.from(bytes).map(b => BASE62[b % 62]).join('')
}

/**
 * Generate a new API key.
 * Returns the full key (shown to user once) and the KV record (stored).
 */
export async function generateApiKey(
  environment: string,
  label?: string
): Promise<{ fullKey: string; record: ApiKeyRecord }> {
  const env = environment === 'production' ? 'live' : 'test'
  const shortToken = generateRandomBase62(6)   // 8 chars
  const longToken = generateRandomBase62(24)   // 32 chars
  const longTokenHash = await hashToken(longToken)

  const fullKey = `fk_${env}_${shortToken}_${longToken}`

  const record: ApiKeyRecord = {
    shortToken,
    longTokenHash,
    label,
    createdAt: new Date().toISOString(),
  }

  return { fullKey, record }
}

/**
 * Parse an API key string into its components.
 * Returns null if the format is invalid.
 */
export function parseApiKey(key: string): ParsedApiKey | null {
  const parts = key.split('_')
  if (parts.length !== 4 || parts[0] !== 'fk') return null
  const [prefix, env, shortToken, longToken] = parts
  if (!shortToken || !longToken) return null
  return { prefix, env, shortToken, longToken }
}

/**
 * Validate an API key against the stored record.
 * Uses timing-safe comparison to prevent timing attacks.
 */
export async function validateApiKey(
  longToken: string,
  storedHash: string
): Promise<boolean> {
  const providedHash = await hashToken(longToken)
  const a = new TextEncoder().encode(providedHash)
  const b = new TextEncoder().encode(storedHash)
  if (a.byteLength !== b.byteLength) return false
  return crypto.subtle.timingSafeEqual(a, b)
}
```

NOTE: `generateRandomBase62(6)` produces 8 characters because base62 encoding of 6 bytes yields ~8 characters. Actually, the modulo approach maps 1 byte -> 1 char, so 6 bytes -> 6 chars and 24 bytes -> 24 chars. Adjust the byte lengths to produce desired character counts:
- shortToken: use 8 bytes to get 8 chars
- longToken: use 32 bytes to get 32 chars

The user stores their admin token securely and uses it to manage keys.

Routes (OpenAPIHono):

```
POST   /v1/keys          - Create new API key (admin token required)
```

For each route:
- Validate admin token from `Authorization: Bearer <ADMIN_TOKEN>` header
- Use timing-safe comparison for admin token validation
- Return responses in Feelr envelope format

**POST /v1/keys:**
- Accept optional `{ label?: string }` body
- Call `generateApiKey(c.env.ENVIRONMENT, label)`
- Store record in KV: `await c.env.AUTH_KV.put('apikey:' + record.shortToken, JSON.stringify(record))`
- Check key count before creating (soft limit ~25): list KV keys with prefix `apikey:` and reject if >= 25
- Return `{ ok: true, data: { key: fullKey, short_token: record.shortToken, label: record.label, created_at: record.createdAt } }`
- The `key` field contains the full API key -- this is the ONLY time the full key is returned

**GET /v1/keys:**
- List all KV keys with prefix `apikey:`
- For each, get the value and parse as ApiKeyRecord
- Return `{ ok: true, data: records.map(r => ({ short_token, label, created_at, last_used_at })) }` -- NO full key or hash in response

**DELETE /v1/keys/:id:**
- `:id` is the short token
- Delete from KV: `await c.env.AUTH_KV.delete('apikey:' + shortToken)`
- Return `{ ok: true, data: { short_token, status: 'revoked' } }`

Later, when Plan 04 creates the formal admin-auth middleware, these routes can optionally be refactored to use it. But for now, inline validation is clean and self-contained.

**1. Upgrade `apps/gateway/src/middleware/api-key.ts`:**

Replace the Phase 1 extraction-only middleware with full validation:

```typescript
import { createMiddleware } from 'hono/factory'
import type { AppEnv } from '../lib/types'
import { FeelrError } from '../lib/errors'
import { parseApiKey, validateApiKey } from '../auth/keys'
import type { ApiKeyRecord } from '../auth/types'

export const apiKeyMiddleware = createMiddleware<AppEnv>(async (c, next) => {
  // Generate unique request ID for tracing
  const requestId = crypto.randomUUID()
  c.set('requestId', requestId)

  // Extract API key: header takes priority over query param
  const headerKey = c.req.header('X-Feelr-Key') ?? null
  const queryKey = new URL(c.req.url).searchParams.get('key')
  const apiKey = headerKey ?? queryKey

  if (!apiKey) {
    throw new FeelrError('AUTH_REQUIRED', {
      message: 'API key required. Include X-Feelr-Key header or ?key= parameter.',
      hint: 'auth',
      status: 401,
    })
  }

  c.set('apiKey', apiKey)

  // Parse key format
  const parsed = parseApiKey(apiKey)
  if (!parsed) {
    throw new FeelrError('AUTH_INVALID', {
      message: 'Invalid API key format. Expected: fk_<env>_<shortToken>_<longToken>',
      hint: 'auth',
      status: 401,
    })
  }

  // Look up key record by short token
  const recordJson = await c.env.AUTH_KV.get(`apikey:${parsed.shortToken}`)
  if (!recordJson) {
    throw new FeelrError('AUTH_INVALID', {
      message: 'API key not found.',
      hint: 'auth',
      status: 401,
    })
  }

  const record: ApiKeyRecord = JSON.parse(recordJson)

  // Validate long token hash (timing-safe)
  const isValid = await validateApiKey(parsed.longToken, record.longTokenHash)
  if (!isValid) {
    throw new FeelrError('AUTH_INVALID', {
      message: 'Invalid API key.',
      hint: 'auth',
      status: 401,
    })
  }

  // Store validated record in context for downstream use
  c.set('apiKeyRecord', record)

  // Update lastUsedAt in background (non-blocking)
  // Use waitUntil to avoid adding latency to the response
  c.executionCtx.waitUntil(
    c.env.AUTH_KV.put(`apikey:${parsed.shortToken}`, JSON.stringify({
      ...record,
      lastUsedAt: new Date().toISOString(),
    }))
  )

  await next()
})
```

Key differences from Phase 1:
- Now REQUIRES a valid API key (throws AUTH_REQUIRED if missing)
- Parses key format (fk_env_short_long)
- Looks up record in KV by short token
- Validates long token hash with timing-safe comparison
- Sets validated `apiKeyRecord` in context
- Updates `lastUsedAt` in background via `waitUntil`

NOTE: The `c.executionCtx.waitUntil` pattern requires the Workers execution context. This is available in the Hono context automatically when running on Workers. For the `waitUntil` call, wrap in a try-catch in case it's not available in test environment -- or better, check if `c.executionCtx?.waitUntil` exists before calling.
