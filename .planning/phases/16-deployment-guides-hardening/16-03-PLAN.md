Add a CI check that validates staging and production wrangler bindings do not share Cloudflare resource IDs, preventing accidental data cross-contamination between environments.

Purpose: Prevents the dangerous scenario where a wrangler.toml edit accidentally shares a KV namespace or D1 database between staging and production, causing data leaks or corruption.

Output: `scripts/check-bindings.mjs` (Node.js TOML parser + set intersection), updated `.github/workflows/ci.yml`

**Step 1:** Install smol-toml as a root devDependency (the script runs from the repo root in CI):

```bash
pnpm add -D smol-toml -w
```

The `-w` flag installs to the workspace root package.json.

**Step 2:** Create `scripts/check-bindings.mjs` -- a Node.js ES module that:

1. Reads `apps/gateway/wrangler.toml` using `fs.readFileSync`
2. Parses it with `smol-toml`'s `parse()` function
3. Defines an `extractIds(envConfig)` function that collects:
   - `kv_namespaces[].id` -- KV namespace IDs
   - `d1_databases[].database_id` -- D1 database IDs
   - Does NOT collect `unsafe.bindings[].namespace_id` -- rate limit bindings intentionally share `"0"` across environments (this is a policy identifier, not a Cloudflare resource ID)
4. Extracts IDs from `config.env.staging` and `config.env.production`
5. Computes set intersection of staging and production IDs
6. If overlap is empty: prints success message with both ID sets and exits 0
7. If overlap is non-empty: prints error listing shared IDs and exits 1
8. If staging or production env section is missing: prints error and exits 1

Include a header comment explaining:
- What the script checks and why
- Why rate limit namespace_id is excluded
- How to run manually: `node scripts/check-bindings.mjs`

The script should use `import.meta.dirname` or `new URL('.', import.meta.url)` to resolve the path to `apps/gateway/wrangler.toml` relative to the repo root (go up one directory from `scripts/`). Alternatively, since CI always runs from the repo root, use a relative path `apps/gateway/wrangler.toml` directly.

Output format on success:
```
Binding validation passed:
  Staging:    KV be026de3..., D1 7a385374...
  Production: KV 69c0aa37..., D1 3395e4fc...
  Overlap:    NONE
```

Output format on failure:
```
ERROR: Staging and production share Cloudflare resource IDs:
  - <shared_id> (found in both staging and production)

This means staging and production environments would read/write the same data store.
Fix: Ensure each environment has unique KV namespace IDs and D1 database IDs in apps/gateway/wrangler.toml
```
