**Prerequisites section:**
- Required tools: wrangler (v4+), az CLI, gh CLI, pnpm, Node.js 20, Go
- Required accounts: Cloudflare (feelr.dev zone), Azure subscription, GitHub (progradetech org)
- Required CLI authentication: `wrangler login`, `az login`, `gh auth login`

**Section 1 - First-Time Setup (DOC-01):**
Comprehensive end-to-end guide with these subsections:

1.1 Cloudflare Account & DNS
- Zone setup for feelr.dev (already done, reference Phase 11)
- Nameserver delegation from Namecheap
- SSL/TLS Full mode, HSTS compliance for .dev

1.2 Gateway Resources (KV, D1, DO)
- Create staging KV namespace: `npx wrangler kv namespace create AUTH_KV --env staging`
- Create production KV namespace: `npx wrangler kv namespace create AUTH_KV --env production`
- Create D1 databases: `npx wrangler d1 create feelr-usage-staging`, `npx wrangler d1 create feelr-usage-production`
- Run D1 migrations: `npx wrangler d1 migrations apply USAGE_DB --env staging`, same for production
- Update wrangler.toml with returned IDs (reference file by path)
- Note: DO (TokenCoordinator) is auto-created on first deploy via `[[migrations]]`

1.3 Gateway Secrets
- Per-environment secrets (staging and production separately):
  - `npx wrangler secret put ENCRYPTION_KEY --env staging` (generate with `openssl rand -base64 32`)
  - `npx wrangler secret put ADMIN_TOKEN --env staging` (generate with `openssl rand -hex 32`)
  - Repeat for `--env production` with DIFFERENT values
  - Optional: SLACK_CLIENT_ID, SLACK_CLIENT_SECRET (from Slack app dashboard)
  - Optional (production only): STRIPE_SECRET_KEY, STRIPE_WEBHOOK_SECRET (from Stripe dashboard)

1.4 Azure SWA Provisioning
- Register resource provider: `az provider register --namespace Microsoft.Web --wait`
- Create resource group: `az group create --name feelr-rg --location eastus2`
- Create dashboard SWA: `az staticwebapp create --name feelr-dashboard --resource-group feelr-rg --sku Standard --location eastus2`
- Create docs SWA: `az staticwebapp create --name feelr-docs --resource-group feelr-rg --sku Standard --location eastus2`
- Both require Standard plan (not Free) for custom domains

1.5 Azure SWA Custom Domains
- Dashboard (app.feelr.dev):
  - Add CNAME record in Cloudflare DNS: `app.feelr.dev` -> SWA default hostname (DNS-only mode, gray cloud)
  - Add TXT record: `_dnsauth.app.feelr.dev` -> validation token from `az staticwebapp hostname show`
  - Map hostname: `az staticwebapp hostname set --name feelr-dashboard --hostname app.feelr.dev`
  - TXT records are permanent (needed for Azure managed SSL renewal)
- Docs (feelr.dev):
  - CNAME flattening at apex: `feelr.dev` -> SWA default hostname (DNS-only mode, gray cloud)
  - Add TXT record: `_dnsauth.feelr.dev` -> validation token
  - Map hostname: `az staticwebapp hostname set --name feelr-docs --hostname feelr.dev`
- IMPORTANT: DNS-only mode (gray cloud) is mandatory for SWA CNAME records -- Cloudflare proxy breaks Azure SSL

1.6 GitHub Actions Secrets
- Retrieve SWA tokens: `az staticwebapp secrets list --name feelr-dashboard --query "properties.apiKey" -o tsv`
- Set secrets in progradetech/feelr repository:
  - `gh secret set CLOUDFLARE_API_TOKEN` (from Cloudflare dashboard > My Profile > API Tokens)
  - `gh secret set CLOUDFLARE_ACCOUNT_ID` (from Cloudflare dashboard > Account Home > Account ID)
  - `gh secret set SWA_DASHBOARD_DEPLOYMENT_TOKEN` (from az CLI output above)
  - `gh secret set SWA_DOCS_DEPLOYMENT_TOKEN` (same for docs SWA)
  - `gh secret set HOMEBREW_TAP_GITHUB_TOKEN` (PAT with repo scope for andrewprograde/homebrew-tap)

1.7 First Deployment
- Deploy gateway staging: `cd apps/gateway && npx wrangler deploy --env staging`
- Deploy gateway production: `cd apps/gateway && npx wrangler deploy --env production`
- Verify: `curl https://feelr-gateway-staging.feelr.workers.dev/health` and `curl https://api.feelr.dev/health`
- Build and deploy dashboard: `NEXT_PUBLIC_GATEWAY_URL=https://api.feelr.dev pnpm turbo run build --filter=@feelr/dashboard`
- Build and deploy docs: `pnpm turbo run build --filter=@feelr/docs`

**Section 2 - Routine Deployments (DOC-02):**

2.1 Gateway Staging (automatic on push to main)
- Triggered by: Push to main affecting `apps/gateway/**`, `packages/**`, or `connectors/**`
- Workflow: `.github/workflows/gateway.yml` (deploy-staging job)
- Manual trigger: `cd apps/gateway && npx wrangler deploy --env staging`
- Verification: Smoke test hits `https://feelr-gateway-staging.feelr.workers.dev/health`

2.2 Gateway Production (automatic on tag push)
- Triggered by: Push of `v*` tag
- Workflow: `.github/workflows/gateway.yml` (deploy-production job)
- Process: versions upload -> 10% canary -> smoke test -> 100% rollout
- Manual trigger: Use gradual rollout commands from gateway.yml as reference
- GitHub environment approval gate protects production
- **WARNING: If release includes new `[[migrations]]` in wrangler.toml, `versions upload` will fail. Use `npx wrangler deploy --env production` directly for DO migration releases.**

2.3 Dashboard & Docs (automatic on push to main / tag push)
- Dashboard staging: Push to main affecting `apps/dashboard/**` or `packages/tsconfig/**`
- Dashboard production: Push of `v*` tag (environment approval gate)
- Docs staging: Push to main affecting `apps/docs/**`
- Docs production: Push of `v*` tag (environment approval gate)
- Workflows: `.github/workflows/dashboard.yml` and `.github/workflows/docs.yml`
- Dashboard builds inject `NEXT_PUBLIC_GATEWAY_URL` for the target environment

2.4 CLI Release (automatic on tag push)
- Triggered by: Push of `v*` tag
- Workflow: `.github/workflows/release.yml`
- GoReleaser builds binaries for linux/darwin/windows amd64/arm64
- Publishes to GitHub Releases + Homebrew tap

**Section 3 - Rollback Procedures (DOC-03):**

3.1 Gateway Rollback
- List recent versions: `npx wrangler versions list --env production --json`
- Rollback: `npx wrangler rollback <VERSION_ID> --env production --yes --message "Rollback: <reason>"`
- Interactive rollback (shows 10 most recent): `npx wrangler rollback --env production`
- Up to 100 versions of rollback history available
- **CRITICAL WARNING: Cannot rollback across Durable Object migration boundaries. If a release included new `[[migrations]]` tags, rollback to pre-migration versions is blocked by Cloudflare. The only option is to fix-forward (deploy a new version with the fix).**

3.2 SWA Rollback (Dashboard / Docs)
- Azure SWA has NO native rollback mechanism
- Option A (preferred): Git revert creates a forward commit, CI auto-deploys
  - `git revert <BAD_COMMIT_SHA> && git push origin main`
- Option B (manual): Checkout known-good commit, rebuild, redeploy
  - For dashboard: `git checkout <GOOD_SHA> && NEXT_PUBLIC_GATEWAY_URL=https://api.feelr.dev pnpm turbo run build --filter=@feelr/dashboard && cp apps/dashboard/staticwebapp.config.json apps/dashboard/out/ && npx @azure/static-web-apps-cli deploy apps/dashboard/out --deployment-token <TOKEN>`
  - Then `git checkout main` to return

3.3 CLI Rollback
- GitHub Releases page: delete the bad release, users on prior version are unaffected
- Homebrew users: `brew install feelr@<prior-version>` or remove bad formula from tap
- No server-side state affected (CLI is a client binary)

**Section 4 - Troubleshooting (DOC-04):**

4.1 Gateway Issues
- Symptom: `wrangler deploy` fails with "could not find binding"
  - Cause: Missing KV namespace or D1 database in wrangler.toml for target env
  - Fix: Verify resource IDs in `apps/gateway/wrangler.toml` match actual Cloudflare resources (`npx wrangler kv namespace list`, `npx wrangler d1 list`)

- Symptom: `versions upload` fails with migration error
  - Cause: New `[[migrations]]` tag present -- versions upload does not support DO migrations
  - Fix: Use `npx wrangler deploy --env production` directly (bypasses gradual rollout)

- Symptom: Health check returns 500 after deploy
  - Cause: Missing or expired Worker secrets (ENCRYPTION_KEY, ADMIN_TOKEN)
  - Fix: `npx wrangler secret list --env <ENV>` to check, then `npx wrangler secret put <NAME> --env <ENV>` to set

- Symptom: OAuth token refresh fails
  - Cause: SLACK_CLIENT_ID/SLACK_CLIENT_SECRET not set or expired
  - Fix: Verify secrets are set for the correct environment

4.2 SWA Issues
- Symptom: SWA deploy succeeds but site shows old content
  - Cause: Browser cache or CDN cache
  - Fix: Hard refresh (Ctrl+Shift+R), or wait ~5 minutes for CDN propagation

- Symptom: Custom domain shows SSL error
  - Cause: Cloudflare proxy (orange cloud) is enabled on CNAME record
  - Fix: Set CNAME to DNS-only mode (gray cloud) in Cloudflare dashboard. Azure SWA manages its own SSL.

- Symptom: Custom domain validation fails
  - Cause: `_dnsauth` TXT record missing or incorrect
  - Fix: Check `az staticwebapp hostname show` for expected validation token, update DNS

- Symptom: Dashboard shows "Failed to fetch" or network errors
  - Cause: `NEXT_PUBLIC_GATEWAY_URL` was wrong during build
  - Fix: Rebuild with correct env var for target environment (staging URL for staging, production URL for production)

4.3 CI/CD Issues
- Symptom: Workflow does not trigger on push to main
  - Cause: Path filter does not match changed files
  - Fix: Check `paths:` section in workflow YAML against actual changed files

- Symptom: Two deploys race on staging
  - Cause: Concurrency group conflict or CI preview and staging deploy running simultaneously
  - Fix: Both ci.yml (gateway-preview) and gateway.yml (deploy-staging) share `deploy-staging` concurrency group -- this is intentional and should queue, not race

- Symptom: Production deploy blocked / waiting
  - Cause: GitHub environment approval gate (expected behavior)
  - Fix: Approve in GitHub Actions UI under the production environment

4.4 DNS & SSL Issues
- Symptom: `api.feelr.dev` not resolving
  - Cause: Cloudflare custom domain not yet propagated, or Worker route not configured
  - Fix: Verify `[[env.production.routes]]` in wrangler.toml has `pattern = "api.feelr.dev"` with `custom_domain = true`. Check Cloudflare DNS for the record.

- Symptom: SSL certificate error on feelr.dev or app.feelr.dev
  - Cause: Azure managed SSL not provisioned yet (can take up to 24 hours), or CNAME is proxied through Cloudflare
  - Fix: Ensure DNS-only mode (gray cloud). Wait for Azure to provision managed certificate. Check `az staticwebapp hostname show`.
