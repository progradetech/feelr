<task type="auto">
  <name>Task 1: Create dashboard.yml workflow with staging and production deploy jobs</name>
  <files>.github/workflows/dashboard.yml</files>
  <action>
    Create `.github/workflows/dashboard.yml` with the following structure:

    **Workflow name:** `Dashboard`

    **Triggers:**
    - `on.push.branches: [main]` with paths: `apps/dashboard/**`, `packages/tsconfig/**` (dashboard extends @feelr/tsconfig)
    - `on.push.tags: ["v*"]` (production deploys on version tag)
    - `on.workflow_dispatch` (manual trigger for ad-hoc deploys)

    **Job 1: deploy-staging**
    - Condition: `if: github.ref == 'refs/heads/main'`
    - Runner: `ubuntu-latest`
    - Timeout: 15 minutes
    - Concurrency group: `deploy-dashboard-staging` with `cancel-in-progress: false`
    - Steps:
      1. `actions/checkout@v4`
      2. `pnpm/action-setup@v4`
      3. `actions/setup-node@v4` with node-version 20 and cache pnpm
      4. `pnpm install --frozen-lockfile`
      5. Build dashboard (staging): `pnpm turbo run build --filter=@feelr/dashboard` with env `NEXT_PUBLIC_GATEWAY_URL: https://feelr-gateway-staging.feelr.workers.dev`
      6. Copy SWA config: `cp apps/dashboard/staticwebapp.config.json apps/dashboard/out/`
      7. Deploy to SWA staging using `Azure/static-web-apps-deploy@v1` with:
         - `azure_static_web_apps_api_token: ${{ secrets.SWA_DASHBOARD_DEPLOYMENT_TOKEN }}`
         - `repo_token: ${{ secrets.GITHUB_TOKEN }}`
         - `action: upload`
         - `app_location: apps/dashboard/out`
         - `output_location: ""`
         - `skip_app_build: true`
         - `deployment_environment: staging`

    **Job 2: deploy-production**
    - Condition: `if: startsWith(github.ref, 'refs/tags/v')`
    - Runner: `ubuntu-latest`
    - Timeout: 15 minutes
    - Environment: `production` (GitHub environment approval gate)
    - Concurrency group: `deploy-dashboard-production` with `cancel-in-progress: false`
    - Steps: Same as staging EXCEPT:
      - Build env: `NEXT_PUBLIC_GATEWAY_URL: https://api.feelr.dev`
      - Deploy without `deployment_environment` (deploys to production slot)
      - No `deployment_environment` parameter at all (omit it entirely)
  </action>
  <verify>
    1. `.github/workflows/dashboard.yml` exists
    2. `grep 'NEXT_PUBLIC_GATEWAY_URL.*staging' .github/workflows/dashboard.yml` matches staging URL
    3. `grep 'NEXT_PUBLIC_GATEWAY_URL.*api.feelr.dev' .github/workflows/dashboard.yml` matches production URL
    4. `grep 'deployment_environment: staging' .github/workflows/dashboard.yml` shows staging env
    5. `grep 'packages/tsconfig' .github/workflows/dashboard.yml` shows tsconfig path trigger
    6. `grep 'SWA_DASHBOARD_DEPLOYMENT_TOKEN' .github/workflows/dashboard.yml` shows correct secret name
  </verify>
  <done>dashboard.yml deploys to SWA staging on push to main (with correct staging gateway URL) and production on v* tag (with correct production gateway URL), scoped to dashboard and tsconfig paths only.</done>
</task>
