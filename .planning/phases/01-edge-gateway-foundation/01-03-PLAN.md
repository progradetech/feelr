  <action>
    Write comprehensive integration tests using @cloudflare/vitest-pool-workers. These tests run inside the actual Workers runtime, catching issues that unit tests would miss. Reference RESEARCH.md integration test example for the testing pattern.

    **Testing pattern:**
    - Import `{ SELF }` from 'cloudflare:test' (the Workers pool-workers binding)
    - Import `{ describe, it, expect }` from 'vitest'
    - Use `SELF.fetch('http://localhost/path')` to make requests to the running Worker
    - Parse response bodies with `await res.json()`

    **routes.test.ts -- Route dispatch tests (GATE-01):**
    Test cases:
    1. Mock echo action returns 200 with correct data shape (message echoed back)
    2. Mock items.list returns 200 with data as array
    3. Unknown connector returns 404 with CONNECTOR_NOT_FOUND code
    4. Unknown action on known connector returns 404 with ACTION_NOT_FOUND code
    5. Health check returns 200 with { ok: true }
    6. Unknown path returns 404 with NOT_FOUND error envelope
    7. POST to mock echo with JSON body works (params from body)
    8. API key accepted from X-Feelr-Key header (returns 200, no validation in Phase 1)
    9. API key accepted from ?key= query param (returns 200, no validation in Phase 1)
    10. OpenAPI doc endpoint returns valid JSON with openapi field

    **envelope.test.ts -- Response envelope tests (GATE-02, GATE-04):**
    Test cases:
    1. Successful response has exactly { ok: true, data: ..., meta: ... } shape (no extra top-level keys)
    2. meta contains request_id (UUID format: 8-4-4-4-12 hex pattern)
    3. meta contains connector name matching the URL
    4. meta contains action name matching the URL
    5. meta contains duration_ms as a non-negative number
    6. List action response has data as array
    7. Single action response has data as object (not array)
    8. List action with pagination has meta.cursor and meta.has_more
    9. ?raw=true returns raw data without envelope (no ok, no meta keys)
    10. All field names in response are snake_case (verify by checking keys of data objects)

    **errors.test.ts -- Error handling tests (GATE-03):**
    Test cases:
    1. Error response has exactly { ok: false, error: { code, message, hint, status } } shape
    2. CONNECTOR_NOT_FOUND: status 404, hint 'abort'
    3. ACTION_NOT_FOUND: status 404, hint 'abort'
    4. Mock error.throw action returns correct error code and status
    5. Error hint is always one of: 'retry', 'auth', 'abort' (test each via mock error.throw)
    6. Error status is always from the normalized set: 400, 401, 403, 404, 429, 500, 502
    7. HTTP response status code matches error.status in the body
    8. Error includes message field (non-empty string)
    9. Error with detail field includes upstream context
    10. 404 for unknown path uses error envelope, not Hono default HTML

    After writing tests, run `pnpm turbo test` (or `cd apps/gateway && pnpm test`) to execute them.

    IMPORTANT: If any tests fail due to runtime issues (not test logic), fix the gateway code in Plan 02's files. Tests are the source of truth for the success criteria.

    CRITICAL: The vitest.config.ts from Plan 01 must be correctly configured for @cloudflare/vitest-pool-workers. If tests cannot find the SELF binding, check that the pool configuration in vitest.config.ts is correct per Cloudflare docs: https://developers.cloudflare.com/workers/testing/vitest-integration/get-started/
