<task type="auto">
  <name>Task 2: Fix sync.yml to regenerate lockfile after subtree pull</name>
  <files>.github/workflows/sync.yml</files>
  <action>
The current sync.yml has a problem: after `git subtree pull`, it runs `pnpm install` which may change the lockfile, then tries to amend the subtree merge commit. This is fragile because:
- If lockfile hasn't changed, the amend is a no-op (fine)
- If lockfile changed, the amend modifies the subtree merge commit (risky with squash)
- The `--squash` flag in subtree pull is noted as problematic in STATE.md blockers

Update `.github/workflows/sync.yml` with these fixes:

1. **Replace the "Install and update lockfile" step** with a cleaner approach:
   ```yaml
   - name: Install dependencies and update lockfile
     run: pnpm install --no-frozen-lockfile

   - name: Commit lockfile changes if any
     run: |
       if ! git diff --quiet pnpm-lock.yaml 2>/dev/null; then
         git add pnpm-lock.yaml
         git commit -m "chore: update pnpm-lock.yaml after OSS sync"
       fi
   ```
   Key change: Use a SEPARATE commit for lockfile changes instead of `--amend`. This avoids corrupting the subtree merge commit and works correctly regardless of whether squash merge is used.

2. **The full updated sync.yml should be:**
   ```yaml
   name: Sync OSS

   on:
     repository_dispatch:
       types: [oss-sync]
     workflow_dispatch:

   concurrency:
     group: oss-sync
     cancel-in-progress: false

   jobs:
     sync:
       runs-on: ubuntu-latest
       timeout-minutes: 15
       steps:
         - uses: actions/checkout@v4
           with:
             fetch-depth: 0
             token: ${{ secrets.GITHUB_TOKEN }}

         - name: Configure git
           run: |
             git config user.name "github-actions[bot]"
             git config user.email "41898282+github-actions[bot]@users.noreply.github.com"

         - name: Add OSS remote and pull subtree
           run: |
             git remote add oss https://github.com/progradetech/feelr.git
             git fetch oss main
             git subtree pull --prefix=oss oss main --squash \
               -m "chore: sync OSS subtree to ${{ github.event.client_payload.sha || 'manual' }}"

         - uses: pnpm/action-setup@v4

         - uses: actions/setup-node@v4
           with:
             node-version: 20

         - name: Install dependencies and update lockfile
           run: pnpm install --no-frozen-lockfile

         - name: Commit lockfile changes if any
           run: |
             if ! git diff --quiet pnpm-lock.yaml 2>/dev/null; then
               git add pnpm-lock.yaml
               git commit -m "chore: update pnpm-lock.yaml after OSS sync"
             fi

         - name: Build and test
           run: pnpm turbo run typecheck test

         - name: Push sync commit(s)
           run: git push origin main
   ```

   Changes from current:
   - Removed `cache: "pnpm"` from setup-node (the lockfile may change, caching on old lockfile causes issues)
   - Split "Install and update lockfile" into two steps: install + conditional commit
   - Replaced `git commit --amend --no-edit` with a separate commit (avoids corrupting subtree marker)
   - Changed step name from "Push sync commit" to "Push sync commit(s)" (may now push 2 commits)
   - Used `--no-frozen-lockfile` explicitly to make intent clear

3. **Commit the sync.yml change:**
