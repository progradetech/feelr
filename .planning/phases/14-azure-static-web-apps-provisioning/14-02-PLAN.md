<task type="auto">
  <name>Task 1: Initiate domain verification and retrieve validation tokens</name>
  <files></files>
  <action>
Read the default hostnames from Plan 01 SUMMARY (needed as CNAME targets).

**1. Initiate TXT validation for app.feelr.dev (subdomain):**
```bash
az staticwebapp hostname set \
  --name feelr-dashboard \
  --hostname app.feelr.dev \
  --validation-method dns-txt-token \
  --no-wait
```

**2. Get the dashboard validation token:**
```bash
az staticwebapp hostname show \
  --name feelr-dashboard \
  --resource-group feelr-rg \
  --hostname app.feelr.dev \
  --query "validationToken" -o tsv
```

**3. Initiate TXT validation for feelr.dev (apex):**
```bash
az staticwebapp hostname set \
  --name feelr-docs \
  --hostname feelr.dev \
  --validation-method dns-txt-token \
  --no-wait
```

**4. Get the docs validation token:**
```bash
az staticwebapp hostname show \
  --name feelr-docs \
  --resource-group feelr-rg \
  --hostname feelr.dev \
  --query "validationToken" -o tsv
```

**5. Present the DNS records the user needs to create in Cloudflare**, clearly formatted with all values pre-filled. Include:
- The exact TXT record names and values
- The exact CNAME record names and values (using default hostnames from Plan 01)
- Explicit instruction that CNAME records MUST use DNS-only mode (gray cloud) permanently
- For apex: instruction to first check and remove any existing A/AAAA records for `@`

Output format for user:
```
=== DNS RECORDS TO ADD IN CLOUDFLARE ===

IMPORTANT: All CNAME records MUST use DNS-only mode (gray cloud icon).
Do NOT enable Cloudflare proxy (orange cloud) -- it will break Azure SSL.

--- app.feelr.dev (dashboard) ---
1. TXT | Name: _dnsauth.app | Content: <TOKEN> | TTL: Auto
2. CNAME | Name: app | Content: <default-hostname>.azurestaticapps.net | Proxy: DNS only (gray cloud)

--- feelr.dev apex (docs) ---
FIRST: Check if any A or AAAA records exist for "@" and DELETE them.
3. TXT | Name: _dnsauth | Content: <TOKEN> | TTL: Auto
4. CNAME | Name: @ | Content: <default-hostname>.azurestaticapps.net | Proxy: DNS only (gray cloud)
   (Cloudflare will auto-flatten this CNAME at the apex)

Keep the _dnsauth TXT records PERMANENTLY -- Azure uses them for SSL certificate renewal.
```

<task type="checkpoint:human-action" gate="blocking">
  <name>Task 2: Add DNS records in Cloudflare dashboard</name>
  <action>
The user must add 4 DNS records in the Cloudflare dashboard. These cannot be automated because the Cloudflare API credentials are not available to Claude (and the project uses the Cloudflare dashboard for DNS management, consistent with Phase 11).
  </action>
  <instructions>
Go to the Cloudflare dashboard for the feelr.dev zone and add the DNS records output by Task 1.

**Before adding apex records:** Check if A or AAAA records exist for `@` (feelr.dev). If they do, delete them first -- Cloudflare does not allow both A and CNAME at the same name.

**For each CNAME record:** Click the orange cloud icon to toggle it to gray cloud (DNS only). This is critical -- Azure SSL certificate provisioning and renewal will fail if the proxy is enabled.

**Records to add (4 total):**
1. `_dnsauth.app` TXT record (dashboard validation token)
2. `app` CNAME record pointing to dashboard default hostname (DNS only)
3. `_dnsauth` TXT record (docs validation token)
4. `@` CNAME record pointing to docs default hostname (DNS only)

After adding all 4 records, wait ~2 minutes for DNS propagation, then type "records added".
  </instructions>
  <resume-signal>Type "records added" when all 4 DNS records are configured in Cloudflare</resume-signal>
</task>
