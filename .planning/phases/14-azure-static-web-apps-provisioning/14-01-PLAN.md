  <action>
Create `apps/dashboard/staticwebapp.config.json` with:
- `responseOverrides.404.rewrite` set to `/404.html`
- `globalHeaders` with `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`

Do NOT add `navigationFallback` -- it conflicts with Next.js per-page HTML generation (`output: 'export'` creates individual HTML files for each route).

Update `turbo.json` build task outputs from `["dist/**"]` to `["dist/**", "out/**"]`. The gateway outputs to `dist/` but both Next.js apps output to `out/` via `output: 'export'`. Without this fix, Turborepo will not cache Next.js static export builds correctly.

<task type="auto">
  <name>Task 3: Create SWA resources, build apps, and deploy</name>
  <files></files>
  <action>
After user confirms Azure login, run the following steps:

**1. Create resource group:**
```bash
az group create --name feelr-rg --location centralus
```

**2. Create SWA for dashboard (Standard plan, no GitHub integration):**
```bash
az staticwebapp create --name feelr-dashboard --resource-group feelr-rg --sku Standard --location centralus
```
If `feelr-dashboard` is taken, try `feelr-app-dashboard` as fallback.

**3. Create SWA for docs (Standard plan, no GitHub integration):**
```bash
az staticwebapp create --name feelr-docs --resource-group feelr-rg --sku Standard --location centralus
```
If `feelr-docs` is taken, try `feelr-app-docs` as fallback.

**4. Get default hostnames** (save these -- needed for DNS CNAME targets in Plan 02):
```bash
az staticwebapp show --name feelr-dashboard --resource-group feelr-rg --query "defaultHostname" -o tsv
az staticwebapp show --name feelr-docs --resource-group feelr-rg --query "defaultHostname" -o tsv
```

**5. Get deployment tokens:**
```bash
az staticwebapp secrets list --name feelr-dashboard --resource-group feelr-rg --query "properties.apiKey" -o tsv
az staticwebapp secrets list --name feelr-docs --resource-group feelr-rg --query "properties.apiKey" -o tsv
```

**6. Store deployment tokens as GitHub Actions secrets** (for Phase 15 CI/CD):
```bash
gh secret set SWA_DASHBOARD_DEPLOYMENT_TOKEN --body "<dashboard-token>"
gh secret set SWA_DOCS_DEPLOYMENT_TOKEN --body "<docs-token>"
```

**7. Build both apps:**
```bash
NEXT_PUBLIC_GATEWAY_URL=https://api.feelr.dev pnpm turbo run build --filter=@feelr/dashboard
pnpm turbo run build --filter=@feelr/docs
```
The dashboard build MUST have `NEXT_PUBLIC_GATEWAY_URL=https://api.feelr.dev` set because Next.js inlines `NEXT_PUBLIC_*` vars at build time. Without it, the dashboard would hardcode `http://localhost:8787` as the gateway URL.

**8. Copy staticwebapp.config.json into out/ directories** (SWA reads config from the deployed directory):
```bash
cp apps/dashboard/staticwebapp.config.json apps/dashboard/out/staticwebapp.config.json
cp apps/docs/staticwebapp.config.json apps/docs/out/staticwebapp.config.json
```

**9. Deploy both apps using SWA CLI:**
```bash
npx @azure/static-web-apps-cli deploy apps/dashboard/out --deployment-token <dashboard-token> --env production
npx @azure/static-web-apps-cli deploy apps/docs/out --deployment-token <docs-token> --env production
```

**10. Verify default URLs respond:**
```bash
curl -sI https://<dashboard-default-hostname> | head -5
curl -sI https://<docs-default-hostname> | head -5
```
Both should return HTTP/2 200.

Record the default hostnames in the SUMMARY -- Plan 02 needs them for DNS CNAME targets.
  </action>
